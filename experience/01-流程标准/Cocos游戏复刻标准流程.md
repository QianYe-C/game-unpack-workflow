# Cocos 游戏复刻标准流程

更新日期：2026-10-09

## 1. 启用条件与适用边界

本流程**仅在用户明确要求“复刻为 Cocos 游戏”“用 Cocos 复刻某游戏”或等价表述时启用**。

仅仅提到 Cocos、要求解包资源、Web 本地化、平台转换、资源编辑、已有 Cocos 工程维护或打包，不触发本流程。不要把本流程自动套用于这些任务。

启用后，本流程补充根目录《工作流说明.md》的目录、日志和项目归档约定；它不改变其他任务的工作方式。

## 2. 开工与移植前准备

1. 先阅读 cocosgame 的《工作流说明.md》。仅使用本解包工具流副本时，也阅读根目录《工作流说明.md》。
2. 确认原版来源、运行平台、原版引擎/版本、复刻范围、目标 Cocos Creator 版本和交付平台。创建项目目录后，将原始输入、分析记录、资源配置、Cocos 工程和输出分别放入工作流规定的目录。
3. **开始场景移植前，先完成资源与配置盘点。**至少登记场景、Prefab/预制体、图片/图集、字体、音频、动画、粒子、配置表、脚本、资源 UUID/引用和分包关系；保存原始文件、清单和哈希。缺失或不可读的项目逐项标明，不能默认为不存在。
4. 建立“原版对象 → 导出文件/配置 → Cocos 资产 → 场景/Prefab 引用”的映射。资源身份以稳定 ID 和所属文件/包为准，不以文件名或目录位置猜测。
5. 将原版首屏、每个主要场景和关键交互录成基线证据，记录设备型号、分辨率、方向、存档/关卡状态和操作步骤。

## 3. 先确定原版设计分辨率

开始搭建前，先查原工程配置、场景/Canvas 设置和实际运行画面，确定原版设计分辨率、横竖屏、UI 缩放策略、适配模式及安全区规则，并记录证据。MuMu 显示分辨率是模拟器输出尺寸，不能直接当作游戏设计分辨率。

在 Cocos 工程中设置相同的设计分辨率和对应适配规则。比较画面时让原版与 Cocos Web 预览使用相同画幅、方向、场景、存档状态和缩放条件。来源证据不足时标记“待确认”，不能声称已严格 1:1。

## 4. 以场景为单位逐项 1:1 复刻

1. 先列出原版场景及其进入条件、跳转关系，确定复刻顺序；从启动场景开始逐场景推进。
2. 每个场景按原版层级还原节点、坐标、锚点、尺寸、渲染顺序、字体、材质、动画、交互热区和资源引用。功能、布局或资源暂缺时记录差异，不用占位结果标记完成。
3. **UI 结构以 Prefab/预制体维护。**可在运行时实例化已制作好的 Prefab；不通过代码临时拼建 UI 节点树或动态创建 UI 组件。列表、弹窗和重复元素也应由可复用 Prefab 组织。
4. 等价的 Cocos 内置组件优先直接使用，例如 Button、Label、Sprite、Layout、Widget、ScrollView、Mask 和原生动画组件；不要重造其已有布局、交互、裁剪或渲染行为。只有内置组件无法表达原版行为时才增加自定义组件，并在移植清单中写明缺口和理由。
5. 原版脚本和配置要追踪实际消费位置，确认资源、状态、事件和组件行为；不能只按字段名或节点名推断运行逻辑。

## 5. 原版分析与不确定项

- 可静态读取的内容先做代码与数据分析：搜索场景入口、资源引用、配置读取、状态变化、事件订阅和实际调用点。
- 原版为 Android 包且 MuMu 可运行时，对不确定行为使用 MuMu 做动态观察。固定模拟器分辨率、方向、存档和操作步骤，记录截图/录屏、日志与关键状态变化。
- 静态结论和动态观测分别记录来源。不能用按移植结果生成的预期值验证移植本身；需要用原版样本或独立证据交叉核对。
- 无法访问原版、MuMu 或必要代码时，记录具体限制、采用的替代证据和未验证范围。

## 6. Cocos 工程操作与 Web 预览

1. 场景、节点、组件、Prefab、资源导入、序列化、保存和预览等 Cocos 编辑器操作使用 Cocos MCP。
2. MCP 返回成功不等于资产已正确落盘。保存后检查目标资产；重要改动还要重新打开场景/Prefab，核对引用、组件类型和层级。
3. 通过 Cocos Web 预览验证移植画面与交互。每个场景至少保留原版与预览的同条件截图；按相同视口对比位置、比例、颜色、字体、遮挡、动画时序和点击区域。
4. 视觉通过不代表行为通过。按钮、场景跳转、滚动、弹窗、状态更新和资源加载分别做交互核对。资源修改后重新预览并更新证据，不能沿用过期截图。
5. MCP 不支持某项操作时，记录缺失能力和受影响资产，不静默改写序列化文件并把它当作已验证结果。

## 7. 移植清单与阶段门禁

每个场景维护一行或一组清单记录：

| 项目 | 记录内容 |
|---|---|
| 原版场景 | 场景名、进入方式、前后跳转 |
| 分辨率与适配 | 设计分辨率、方向、缩放和安全区 |
| 资产/配置 | 资源清单、稳定 ID、引用关系、哈希、缺项 |
| Cocos 结构 | 场景、Prefab、原生组件和自定义组件说明 |
| 行为 | 操作步骤、预期状态、跳转、音频/动画反馈 |
| 证据 | 原版代码/配置依据、MuMu 截图或录屏、Web 预览截图 |
| 差异与风险 | 未实现、近似处理、待确认及影响范围 |
| 状态 | 未开始 / 进行中 / 阻塞 / 已验证 |

阶段状态只有在证据齐全后才可标记“已验证”：

- **准备门禁：**输入、场景、资源和配置完成盘点；未知项和缺失项已列出。
- **场景门禁：**该场景的 Prefab、内置组件、布局和交互均有映射与预览证据。
- **整体门禁：**所有范围内场景逐项核对，关键跳转和资源加载可运行，差异和未验证项明确列出。

完成后将移植清单、关键截图/录屏、日志、资源映射、构建信息和阶段复盘一并归档。不得以“能启动”或单张首页截图代替全范围验收。
