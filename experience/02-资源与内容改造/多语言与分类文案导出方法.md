# 多语言与分类文案导出方法

更新时间：2026-03-10  
来源：U3D 本地化与配置导出实战

## 使用说明（示例与通用边界）
- 文中 `sourceConfigs/<project>/`、`Main_Level_1.json`、`Story_3.json` 是输出示例。
- 文中 `categoryTypeId` 为常见分类字段示例，实际字段名可不同。
- 重点是“配置解引用 + 本地词表映射 + 可读化输出”的方法链路。

## 目标
- 将“关卡-角色-图片-分类文案（中文）”导出为可读 JSON。
- 尽量基于本地词表，不依赖线上接口。

## 基本思路
1. 先导出关卡配置（每关一个 JSON）。
2. 解析每格人物 ID、资源引用（分图 png）。
3. 解析分类字段（例如 `categoryTypeId`）。
4. 从本地多语言词表解析 `categoryTypeId -> 中文文案`。
5. 产出“每关可读配置”，用于策划/美术直接编辑与核对。

## 关于 I2 本地化机制（Unity 常见）
- 运行时通常通过 I2Localization 的 key 查表返回文本。
- 表数据常在本地资源中（ScriptableObject / TextAsset / CSV / 二进制文本表）。
- 若未走网络，本地词表应可还原 key -> zh-CN 映射。

## 导出产物建议
- 目录：`sourceConfigs/<project>/`
- 每关一个文件（示例）：
  - `Main_Level_1.json`
  - `Story_3.json`
- 字段建议至少包含：
  - `levelId`
  - `mode`
  - `cells[]`（人物 ID、png 文件名）
  - `categoryTypeId`
  - `categoryNameZh`

## 核验规则
- 同一关卡内每个角色 ID 都能找到 png 映射。
- `categoryTypeId` 必须可解析到中文；缺失时保留未解析标记并记录日志。
- 不允许“仅靠文件名猜分类”，必须保留配置来源路径。

## 常见误区
- 误把关卡顺序当资源顺序：应以配置表与流程状态机决定。
- 误判为走网络翻译：先看日志与本地词表，再判断是否远程配置。
