# 按需模块拆分的跨界面服务审计

## 适用范围

拆分懒加载界面或功能模块时，用于检查跨模块调用、持久服务和销毁行为。

## 审计步骤

1. 同时检查序列化引用、运行时组件查找、路径查询、事件订阅和外部回调。Prefab 内引用少不代表模块没有跨界依赖。
2. 将界面不在场时仍须工作的能力放在常驻服务宿主，例如公共提示、奖励/支付回调和全局事件。显示一条提示不应为了加载完整功能面板。
3. 对公共宿主与模块边界做逐字段配置比较和实际画面对照；仅凭节点数量或 API 返回成功不能证明视觉和行为等价。
4. 覆盖模块从未加载、重复登记、并发请求、关闭界面、销毁场景、加载失败和重试。确认监听者只绑定一次，旧实例注销不会清理新实例。
5. 拆分前后分别测首屏依赖、总包体、初始化耗时、帧时间和 Draw Call。减少常驻节点不自动意味着减少总包或运行开销。
6. 延迟加载组件若错过启动布局事件，应按原布局规则补算一次，并回归后续 resize、横竖屏及不同加载顺序。避免每帧遍历整棵场景树来补偿。

## 完成标准

公共服务独立于界面生命周期；每个跨模块调用都有明确所有者、失败路径、重试策略和销毁清理。结论附配置差异、实际画面及性能数据。
