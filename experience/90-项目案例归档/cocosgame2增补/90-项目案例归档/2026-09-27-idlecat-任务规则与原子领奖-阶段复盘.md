# Idlecat 任务规则与原子领奖阶段复盘

日期/重组日期：2026-09-27。此阶段完成原版规则对照与经济事务；任务模块和整游均未完成。

## 目标与原版证据

按原版 Mission_manager 移植每日任务与赛季奖励。原组件124352、既有 Mission_maanger.prefab；原生代码与只读 MuMu 静态表交叉核对。源项目 sourceConfigs/MissionModule.json、MissionRuntimeSource.json 与 logs/native-*.asm.txt 保存证据。

## 根因与处理

- 静态奖励表会被 Reward_Balance_Apply 运行时重算，不能把导出的表直接当所有赛季配置。首赛季与后续赛季的钻石/武器/核心分支不同；高级武器是型号+5，并非数量三倍。
- 每日任务与赛季重置不同：每日保留经验和赛季领取记录，赛季清零并按日历加一个月。可信时间仍有 ready、20秒等待、未核对账本数量等条件，不能简化为本机日期改变即清零。
- 发奖与领取标记分开保存会导致重启重复发奖或丢奖励。GameEconomy 先构造包含全部变化的提案，保存成功后才替换内存状态和发送事件。
- 广告请求使用会话 token，取消、读档和旧回调不再生效；保存失败保留可重试状态。该约束不替代真实广告 SDK 完成信号。

## 验证结果

- Unicorn 直接执行原 ARM64 算法，只替换 UI 与 analytics。4187项对照覆盖8组赛季奖励表、经验、状态、float32进度、排序优先级、领取先后及滚动目标。
- 跨日、月底/闰年、时间门禁、背包满、重复领取、会话广告回调、存档隔离检查通过。
- 经济事务注入 storage full，验证钻石、武器收藏/等级计数、核心及领取标记全部回滚；签到/矿山相关回归通过。
- assets范围类型检查通过。CLI 20260927-111115 构建 success=true、sourceUnchanged=true，18.23秒；未调用编辑器预览/运行。
