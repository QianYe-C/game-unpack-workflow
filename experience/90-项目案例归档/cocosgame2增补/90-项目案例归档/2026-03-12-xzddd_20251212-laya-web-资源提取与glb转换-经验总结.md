# xzddd_20251212 Laya Web 资源提取与 GLB 转换经验总结

## 项目目标

把线上 Laya 小游戏 `xzddd_20251212` 转为可本地运行的 Web 工程，并进一步完成：

- 全资源预取
- 模式配置表导出
- 图片资源提取为 `png`
- 模型 + 材质 + 贴图 + 动画 转为 `glb`
- 资源平铺整理，便于导入 Cocos

## 关键结论

### 1. 先补全资源链，再做提取和转换

Laya 项目不能只看首页能否打开。真正稳定的流程是：

1. 先把线上入口、分包、懒加载资源全部补齐到本地
2. 再导出配置表、图片和模型
3. 最后做统一整理和平铺

如果直接跳到模型转换，通常会被运行时懒加载资源、模式分包、动态材质引用卡住。

### 2. 可导出的 3D 资源不是单文件，而是一整条资源链

角色或 Boss 这类“完整模型资产”不能只看 `.lh`，而要同时具备：

- `.lh`：层级、节点、组件、骨骼引用
- `.lm`：几何网格
- `.lmat`：材质
- 贴图文件：`png/jpg`
- `.lani`：动画

也就是说，真正可复用的输入链路是：

`.lh + .lm + .lmat + 贴图 + .lani`

不是所有 `.lh` 都是完整模型。有些只是：

- 特效壳子
- 数字牌
- 拖尾
- 空节点/控制节点
- 运行时容器

这些资源就算能导出，也不一定适合作为正常 3D 模型使用。

### 3. 最稳的转换方式不是硬解析格式，而是复用 Laya 运行时

这次最稳定的方案不是离线纯解析 `lh/lm/lani` 私有格式，而是：

1. 用浏览器里的 Laya 运行时把资源正常加载起来
2. 把运行时里的层级、网格、骨骼、动画数据转成 Three.js 对象
3. 再由 `GLTFExporter` 导出为 `glb`

这样做的优势：

- 少踩 Laya 私有二进制格式坑
- 可以直接复用 Laya 已经解析好的网格、动画、材质引用
- 更容易定位“是源数据问题，还是导出逻辑问题”

## 这次踩到的几个关键坑

### 1. 生成了 GLB，不代表 Blender 能导入

一开始虽然能导出 `.glb`，但 Blender 报：

`Couldn't parse glTF. Check that the file is valid`

后面证明这类问题不能靠“文件存在”判断，必须加校验器。

本次用 `@gltf-transform/cli validate` 做强校验，实际抓出的硬错误包括：

- 顶点颜色里出现 `NaN`
- `skin.skeleton` 没指向公共根骨骼

经验：

- 只要 Blender 报解析失败，第一时间跑 glTF 校验器
- 不要只看文件头、chunk 和大小

### 2. 顶点颜色字段名不能想当然

一批模型里，颜色数据不是 `x/y/z/w`，而是 `r/g/b/a`。

如果仍按 `x/y/z/w` 读，导出的颜色缓冲就会带 `NaN`，进而让整个 glTF 失效。

经验：

- Laya 的向量、颜色、权重对象要分别兜底
- 不同字段类型不能共用“看起来像 Vector4”的读取逻辑

### 3. 骨骼根节点必须修成公共祖先

SkinnedMesh 导出时，如果 `skin.skeleton` 指到错误的骨头，比如直接指向 `Spine1`，glTF 校验会报：

- `SKIN_SKELETON_INVALID`

这次正确做法不是改 joint 顺序，而是：

1. 保留原 joint 顺序，避免破坏 skinIndex 对应关系
2. 在导出后的 glTF JSON 中，把 `skin.skeleton` 回写为所有 joints 的公共根节点

这样既不破坏蒙皮，也能满足 glTF 规范。

### 4. 模型翻面问题，本质是绕序不一致

导入 Cocos 后发现“模型面的方向反了”，最终确认不是法线贴图问题，也不是 Cocos 导入器问题，而是三角面绕序问题。

实际验证方法：

1. 取 Laya 原始网格的三角面
2. 用三角面的叉乘法线和顶点法线做点积统计
3. 发现绝大多数三角面都是“面法线与顶点法线相反”

例如：

- `player4`：前 5000 个三角里 4996 个是反向
- `Chest_5`：1592 / 1592 全反
- `Map_XiaoHuoCheV3`：几乎全反

结论：

- 这批源网格基本是“顺时针为正面”
- `glTF / Cocos` 通常按“逆时针为正面”

修复方式：

- 导出时统一把每个三角索引 `(a, b, c)` 翻成 `(a, c, b)`

修复后再次统计，`player4` 变成前 5000 个三角里 4996 个正向，证明绕序修复是正确的。

### 5. 自定义 shader 要允许降级

这批材质里有 `Laya.ToonLite1` 之类的自定义 shader。

如果导出时强依赖这些 shader 完整可解析，批量转换很容易失败。

这次做法是：

- 材质解析失败时，降级到通用材质
- 同时保留原材质信息到自定义字段

经验：

- 导出 glTF 时，优先保证结构和贴图链路正确
- 风格化 shader 不是第一优先级

## 可复用工作流

以后再做类似的 Laya 项目，建议直接按这条顺序执行：

1. 先转本地 Web 工程，确保首页和入口可运行
2. 预取全部懒加载资源和模式分包
3. 导出模式配置表
4. 提取图片并统一转 `png`
5. 用 Laya 运行时加载 `.lh` 资源链，再导出 `glb`
6. 对 `glb` 跑规范校验，不合格的先修再批量
7. 如果目标是 Cocos，再检查一次三角绕序是否一致
8. 最后根据使用场景输出“原始结构版”和“平铺版”

## 这次最值得记住的三条

- Laya 模型导出最稳的入口不是文件格式本身，而是运行时。
- Blender 能不能导入，必须靠 glTF 校验器说话。
- Cocos 里看见整批翻面，优先查三角绕序，不要先怀疑贴图和法线。
