# 狩猎粒子跨模式寿命调查

2026-09-28。本阶段取得原版跨模式寿命证据，尚未修改或验收移植版生命周期；整体目标仍进行中。上一轮补充性能门禁属于文档进展，原版退出采样曾超时且没有退出事件，不能作为生命周期通过证据。

## 原版实测

在 MuMu 原版使用 Frida 主线程有界采样，读取 Particle_Polling.instance_slime 的原 ParticleSystem、粒子 seed/剩余寿命/位置及地图、结算、发射器 activeInHierarchy。每三帧采样，最多60秒；采样结束 detach。只保存前16粒详情，数量读取完整池。

两次普通 UI 退出分别采集340/390帧，GiveUp时57/27粒。结算后粒子继续消散，普通领取时已为0；地图关闭后全局发射器仍启用。这两组不证明带存活粒子的退出行为。

第三组明确为受控运行时测试：手动点击原版 Exit 触发 Game_GiveUp，1200ms后在主线程调用原版 Game_Exit。没有直接修改存档字段，也没有调用付费或广告；原方法正常处理本场0奖励并返回首页。该组用于观察生命周期，不证明普通按钮最早可点击时间。

- GiveUp时19粒。
- 地图首次关闭的采样为17422ms，发射器仍 activeInHierarchy，残留8粒；最大采样剩余寿命1.226717秒。
- 同一seed跨地图关闭继续递减，95组寿命关系检查通过；关闭后1283ms，数量自然降至0。
- 排除了“退出立即Clear”和“地图关闭时暂停这些粒子”两种实现。
- 1096帧记录中的受控 NativeFunction 调用没有触发普通 exit Interceptor；依据相邻帧的地图状态、同seed寿命及 probeIssued 验证转变，不能凭缺少exit事件判断没退出。后续采样工具补了显式probeExit前后快照和4秒退出终止条件，本组原始记录不回填。

原始证据：docs/evidence/particle-lifecycle-20260928/。包括两个被动采样、受控采样、verified-summary.json及native-return.png。verify_hunt_particle_lifecycle.py可重新检查身份、寿命递减和自然归零。

## 移植版差异与下一步

NativeHuntDepthOrder构造时把整个NativeTreeDeathParticles服务节点迁入地图的actors宿主。NativeHuntWorld.clear随后隐藏map，因而原ParticleSystem也失去activeInHierarchy；Creator 3.8.8 onDisable移除beforeRender，组件不再update。这与原版独立全局发射器不一致。若此时仍有粒子，生命周期会被冻结，重入可能恢复旧粒子。当前Cocos正常退出有1.5秒延迟，尚未实测该时序下实际残留数量，不能声称已复现用户可见残影。

矿山也把服务节点迁入地图，clear额外调用ParticleSystem.clear；是否违背原版矿山行为尚需单独采样，不能用Slime证据替代。

下一步实现方向：保留原全局发射器和模拟层级，用MCP创建独立可编辑的绘制占位节点引用原模型，参与模式身体排序。需要同时验证地图隐藏/切回主线期间原模型仍按原版显示、没有UI/3D双提交、没有提前隐藏，以及重入时旧粒子按实际寿命消失。现有NativeParticleDrawSlot支持remote particles，但UIMeshRenderer在提交时_detachFromScene，在onDisable只移除UI注册，不自动恢复3D提交；因此不能仅把绘制节点关掉就宣称修复。先解决这一生命周期契约，再修改序列化绑定。

禁止为此复制粒子池、每帧新增全池扫描、手动重复simulate或通过Clear掩盖差异。沿用单个原模型，性能验收仍以同输入帧耗/长帧/内存优先；50 DC不是硬上限。
