# 游戏活动配置与弹窗链路核验

重组日期：2026-09-09。新增知识点：配置缓存与真实接口互证、资格与弹出分层、商品档位推进与消费分群区分。项目实例为 canting，具体参数只写在案例和项目目录中。

## 从字段查到接口

先搜索字段的定义和读取，再追 `GetServerConfig` 的数据来源，区分“从缓存读取模型配置”与“发 HTTP 下载”。`LoadServerConfig` 可能只是内存分派，不是网络接口。核查登录请求是否携带全部配置键及 MD5；响应省略键有时表示删除，不能直接当增量合并。

沿实际调用点列出启动、升级、回到前台、公告点击、活动到点等刷新场景。检查事件顺序：升级事件可能先于登录取回配置发生，因此拿到升级礼包配置后未必立即触发礼包。

## 缓存与真实响应互证

只读取目标游戏的目录；先记录源文件摘要和时间，再复制稳定快照。数据库需验证格式、长度和摘要；不能靠“能解出几句 JSON”判断成功。导出时只写 config 表，不把身份或会话凭据混入研究 JSON。保留逐阶段快照，便于比较升级前后新增的键。

得到用户授权使用其当前会话后，凭据仅在内存用于原服务；重建二进制字段顺序、整数编码、压缩和签名，禁止把凭据送到临时第三方服务。日志只记录状态、响应大小、配置数量与校验结果。真实 API 的 HTTP 成功、协议 rcode、完整解析和缓存 MD5 一致性应分别核验。

## 规则归因

将四个层次分开记录：

1. 服务端下发的活动资格、组和商品。
2. 客户端激活、过期、冷却与档位推进。
3. 弹窗队列场景、教程/UI 锁、优先级和额度。
4. 手动商店入口或资源不足专用入口。

配置中的月消费字段不自动证明后台实际使用该筛选，也不证明存在推荐模型。客户端取第一条配置而不比较消费区间，只能支持“可能先经服务端筛选”。需要服务端实现或对照样本才能进一步确定。

价格变化应先排查预设档位。购买推进、超时推进、按星期换组与根据消费习惯定价是不同机制。价格需沿 `payID → 商品表 → realMoney/currency → 按钮` 追踪；`desc_price`、折扣比率和内部 fixedMoney 可能有不同含义。未确认的金额单位保持原值。

不要只按配置键是否含Gift/Bundle/Pack或是否出现payID筛选礼包。逐一检查活动模型中的StartPurchase、商品常量、活动定义的商品组映射；通行证、VIP奖励轨道、结束后延时包可能没有服务器payID。对每个已取得配置键保留审计结果，再分别列出人民币商品、游戏货币兑换和免费奖励。标准Bundle模型覆盖率与其他付费活动分开统计；原表已归档但分析遗漏时，应修正文档和生成器，另建补充归档，不改历史快照。

同名时长字段应追到使用位置：允许购买的时间窗口、实际活动延长时长、回收截止可能是三个不同条件。奖励表中的price也需追到实际消耗币种。服务器MD5相同但缓存存在客户端补字段时，索引同时保留内容摘要，避免按MD5合并丢失原始内容差异。

## 验收边界

原版资源呈现、Nest 协议集成通过、真实配置拉取成功、完整主场景可交互是四个独立结果。标题页或 main() 被调用不能算整条启动流程成功。研究报告应给出源文件与函数索引，并明确哪些规则有真实下发实例。

## 将原会话接入本地调研

以用户授权的当前游戏会话为边界，后端使用真实 token 请求原服务，浏览器使用另一份本地会话标记。标记同样要满足客户端格式检查（本例为 Base64），不能任意加前缀。未知业务接口也不要随意返回 401/403，原客户端可能把它解释为令牌过期并无限重登。订阅状态、自动存档等启动附带写操作必须明确决定本地保存或不支持，不能因通用代理而意外上传生产账号。

读取缓存时遵循完整 SDK 约定：`WXReadFileSync` 返回长度后，客户端还会通过 `WXSetArrayBuffer` 将缓存复制到 WASM 内存。不要 JSON.stringify 未知 SDK 参数里的整个 HEAPU8；记录类型和字节数即可。真实启动验证要覆盖刷新、主场景、手动礼包窗口，以及最近一次刷新的错误日志，避免被旧日志误导。

## 进度对照与完整归档（2026-09-09重组）

对照实验必须同时记录等级、主线任务、建筑状态和采集时间。直接改变等级只能证明该状态下配置变化，不能代替完整自然升级样本。建筑状态应由对应任务剧情的slot写入操作恢复，不能把所有槽位设为同一值；内容开放上限以服务器时间配置为准，不能使用包内未开放章节。

将所有已取得服务器配置、包内表、规则和价格映射保存为独立快照，附请求键覆盖、原始上下文和SHA-256清单。单独保存API与客户端缓存；MD5一致的表仍可能被客户端补字段/改排序，因此应同时比较实际内容。归档不混入原始会话库或完整账号存档。用户要求稍后还原时，先保留调研证据，不让刷新配置覆盖对照样本。

## 2026-10-08：入口和关卡数量的证据口径

首页入口数量先查注册列表与显示条件，再匹配当前存档的实验组；资源包含有多个表现 Prefab 不等于有多个入口。关卡数量分别记录主线独立布局、无尽顺序记录、去重资源和取模周期。表格中的解锁字段若未被实际触发函数读取，应按运行时所读取的条件还原，同时留存原字段，避免把配置外观误作行为。案例见 Rotate Rings 2026-10-08 阶段复盘。
