# 资源导出修改回写统一范式

更新时间：2026-03-11  
来源：多项目实战沉淀（案例见 `experience/90-项目案例归档/`）

## 使用说明（示例与通用边界）
- 文中 `Main_Level_N`、`Story_N`、`Others` 属于目录组织示例。
- 文中 `sourceImages`、`manifest`、`atlas` 为通用概念示例，可按项目实际命名映射。
- 重点是“分图编辑 -> 映射管理 -> 合图重建 -> 回写校验”的闭环思路。

## 目标
- 导出后只面对“分图/可读配置”进行编辑。
- 回写时由脚本负责还原到游戏真实资源格式。
- 避免人工改合图导致映射错位、CRC 错误、游戏不生效。

## 导出标准（sourceImages）
- 根层级允许：
  - `Main_Level_N/`（主线关卡分图）
  - `Story_N/`（故事模式分图）
  - `Others/`（其他 Level 资源分图）
  - 根目录平铺分图（非 Level 贴图）
- 不在 `sourceImages` 保留任何合图（Atlas 仅作为中间产物）。

## 映射标准
- 维护独立映射文件（例如 manifest/json）：
  - 分图文件名 -> 合图名 -> 裁切位置/尺寸
  - 分图文件名 -> 目标包/目标资源路径
  - 关卡与资源包关系（由配置表推导，不靠文件名猜测）

## 回写标准
1. 读取映射，先检查分图尺寸与原始尺寸一致。
2. 需要合并的资源先重建合图（临时产物，不落 `sourceImages`）。
3. 用重建后的合图回写目标包/目标文件。
4. 写回后做完整性校验（哈希/CRC/可加载性）。
5. 运行游戏验证修改是否在目标场景生效。

## 典型故障与处理
- 修改后不生效：
  - 先查是否回写到了真实被引用的合图。
  - 再查 UnityCache/浏览器缓存。
- 进入下一关报 bundle CRC/404：
  - 说明写回后包体内容与索引/manifest 不一致，需重建并校验全链路。
- 文件名与内容错位：
  - 说明映射错配，禁止按文件名猜路径，必须按配置表/映射表回写。

## 图片资源名错位（本次高频卡点）专项规范
- 现象（以 `drgm_ljpx2_lt` 为例）：
  - 分图文件名看似正确（如 `...__0003_159.png`），但图片内容对应另一个角色。
  - 进而导致“按分类分目录”看起来错乱（例如 `ct198_蓝发` 目录里出现老人/戴帽子）。
- 真实根因：
  - 不能假设 `SpriteAtlas.m_PackedSpriteNamesToIndex` 与 `m_RenderDataMap` 是同序一一对应。
  - 实际存在“名称顺序”和“渲染数据顺序”不一致的情况，按索引硬配会错位。
  - 还存在“像素在当前 Atlas 包，Sprite 元数据在共享包”的跨包结构；只看单包会丢失正确映射。
- 正确做法：
  - 用 `Sprite.m_RenderDataKey` 建立映射，不用“同索引猜测”。
  - 建立双向表：`atlasTag + spriteName -> renderKey`，`atlasTag + renderKey -> spriteName`。
  - 再用 `renderKey -> renderData(textureRect)` 裁切，最终得到正确 `spriteName -> png`。
  - 对外统一稳定主键：`imageKey = bundleHash#atlasIndex`，不要只靠文件名做身份标识。
- 强制门禁：
  - 抽检至少 1 个已知关卡（例如 NH1）做“游戏内布局 vs 导出文件”人工对照。
  - 全量校验必须按 `(itemId, groupId)` 计数比对，不能把 `itemId` 当全局唯一键。
  - 通过后再允许批量按分类重组与回写。

## 最小门禁
- 关键分图修改在游戏内可见。
- 关卡切换无新增 CRC mismatch。
- 回写日志可追溯到“分图 -> 合图 -> 目标资源”链路。

## Unity iOS 单包提取补充

重组日期：2026-08-11  
新增来源：Light Up Sort iOS Unity IL2CPP 资源提取案例

- iOS Unity 单包的资源主体可直接位于 `<App>.app/Data/data.unity3d`，应先做对象类型与 SerializedFile 清点，再决定是否存在 Addressables 或外部分包。
- `PathID` 只在单个 SerializedFile 内稳定；跨文件清单统一使用 `(assetsFile, pathId)`，不能把 PathID 当作全包唯一键。
- IL2CPP 业务 MonoBehaviour 缺少 TypeTree 时，仍可读取 Unity 通用对象头。对于只包含数组/PPtr 的索引对象，可从原始序列化数据恢复引用链，但必须校验数组长度、目标对象类型和解析唯一性。
- Sprite 导出应追踪 `Sprite.m_RD.texture`：裁切后的 Sprite 进入可编辑美术目录，底层合图留在日志或中间层；没有 Sprite 引用的独立纹理再作为 Texture2D 输出。
- `0 × 0` 的 `Font Texture` 常是占位对象，应在清单中标为不可导出，而不是当作资源损坏或中断全流程。
- Mesh、Material、Texture 应分别保留稳定映射；裸 Mesh 可先导 OBJ，若要还原完整关卡模型，还需继续解析 Transform、Renderer 和材质实例链。

## 2026-09-27 重组：UI 遮罩启用状态与九宫格单位

跨引擎还原应同时读取 MonoBehaviour 头部 enabled 与自定义字段，不能看到 Mask 组件就默认启用。Unity 禁用 Mask 时仍可能绘制同节点 Image；目标引擎若把 Mask 和内部渲染器联动禁用，需要保留独立 Image 语义。

九宫格的源 inset/UV 使用纹理像素，几何边框使用界面单位。Unity Image 的换算为 Canvas.referencePixelsPerUnit / (Sprite.pixelsPerUnit × Image.pixelsPerUnitMultiplier)。目标引擎不自动换算时，应只修正顶点几何，不能缩小 SpriteFrame inset 导致错误采样。验证覆盖小于边框和的矩形、非居中锚点、零尺寸及动态填充恢复。

案例：[idlecat 静态遮罩像素比例](../90-项目案例归档/2026-09-27-idlecat-静态遮罩像素比例-阶段复盘.md)。

## 2026-09-27 重组：动态填充与图片遮罩

九宫格填充不能通过缩短底图尺寸替代裁切；原边框与 UV 应按完整矩形生成。迁移时可在作者态将完整尺寸的 alpha stencil 与动态矩形相交，再让可见底图与滚动条纹都位于该交集内。保留原控制器绑定并测试零值、原浮点阈值、满值、显示恢复和条纹相位。

离线加载的 Prefab 可能含已序列化 Graphics，而 Mask 内部缓存尚未建立。只设置 Mask.type 未必能清除冲突渲染器；通过编辑器组件 API 明确清理再恢复渲染类型，随后检查序列化结果。资源编辑/导入可能触发浏览器预览自动重载，完整流程验收应在最后一次资源更改后进行。

案例：[idlecat 动态进度遮罩](../90-项目案例归档/2026-09-27-idlecat-动态进度遮罩-阶段复盘.md)。

### 2026-09-27：文本显示串与输入值分离

移植输入组件时，原生显示串可能比业务值多出零宽字符；即使不产生像素，它仍可能影响字体字距与居中。分别采集键盘值、组件值、Label.text和characterInfo，再用原生坐标回归；显示用字符不得写入长度限制、键盘回填或提交值。移动端由系统键盘绘制光标，不足以证明桌面光标可以省略。案例：[idlecat输入显示末尾字符](../90-项目案例归档/2026-09-27-idlecat-输入显示末尾字符-阶段复盘.md)。

### 2026-09-27：输入光标不能按配置字面值绘制

原TMP caretWidth还会经过字体pointSize、faceScale、lineHeight与常量缩放；混合字体的光标上下界取相邻字符指标，空白字符用当前位置累积行高。采集原VertexHelper顶点作为几何证据，并区分正常移动端系统键盘与受控原地绘制分支。案例：[idlecat输入光标选区几何](../90-项目案例归档/2026-09-27-idlecat-输入光标选区几何-阶段复盘.md)。

### 2026-09-27 动态换图与动画组件核对

原prefab中保留Bounce等命名节点不等于已迁移动画；核对启用时执行组件及池节点复用生命周期。Unity换图后的SetNativeSize、子级stretch anchors、翻转文字的反向旋转须与sprite赋值一起移植；静态初始矩形不足以验证不同等级图片。证据与复盘见[鱼与宠物视觉反馈](../90-项目案例归档/2026-09-27-idlecat-鱼与宠物视觉反馈-阶段复盘.md)。


## 2026-09-27：粒子启停时序与资源导入

- 粒子原节点active/playOnAwake必须结合祖先启用、协程和Spawn顺序分析；场景启用时间不一定等于战斗开始，刷新血条也不等于重新出场。
- Unity梯度数组有固定容量，仅读取m_NumColorKeys/m_NumAlphaKeys有效元素；未使用槽位可能含旧颜色，错误导入会产生无原版依据的色变。
- 外部写入的新JSON先通过asset-db refresh目标目录并查询UUID；reimport成功返回不代表新文件已注册。同名import可能弹原生覆盖框并阻塞MCP，应检查对话框并取消，再按资源登记流程处理，不直接判断为崩溃。
