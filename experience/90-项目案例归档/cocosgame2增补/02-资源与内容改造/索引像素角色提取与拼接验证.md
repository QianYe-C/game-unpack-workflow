# 索引像素角色提取与拼接验证

知识重组日期：2026-09-08。来源：qiannian 人物阶段复盘。适用于有原始包和可运行程序、但没有编辑器图集配置的索引色像素角色。

## 先确定原始存储和实际显示链路

不要因运行平台支持图块就假定所有源图都是图块。原素材可能按行存储，程序先拼接，再转换为显存格式；不同年龄或角色类型也可能使用不同路径。需要同时保存源字节、运行时缓冲区和显示结果，并寻找相互转换的函数。

每个导出部件保留来源校验、资源 ID、资源偏移、帧地址、原始头、尺寸、索引像素和透明规则。以原帧地址去重，将资源身份与显示编号分开。空帧必须作为合法数据记录，不能默认为提取失败。

## 恢复坐标与颜色语义

将身体、头型、五官分成各自的挂点关系。读取调用方如何使用元数据，而不是靠截图手工调整一组固定偏移。特别检查有符号转换、整数溢出、位打包导致的对齐、镜像发生在哪一步，以及条件覆盖的层级。

保留调色板索引，透明依据索引而非 RGB。预览 PNG 的颜色与最终人物调色板要写明区别。颜色条目数量通常来自资源，不应硬编码为所有角色相同。查找跨资源边界时先核对原程序行为，不能把导出后的单文件边界当成原程序访问边界。

## 用原程序建立独立对照

环境允许时，在可控运行器中调用原合成函数，把输入配方和输出像素／palette 固化为夹具。新实现必须独立生成结果，再比较所有像素索引和可见颜色；不要用新实现生成它自己的预期值。

同时保存真实游戏显示样本作第二条证据链，避免调用约定、内存初始化错误导致“两个错误实现互相吻合”。年龄临界值、多个资源组、正背、帧、色表、特殊缺帧应包含在验证范围中。

## 明确素材能力与游戏语义的边界

发现闭眼、开口素材只能证明有相应视觉形态；确认眨眼或说话需查到替换时序，确认情绪机制还需查到事件状态到素材的映射。显示方向、帧索引、资源组、动作语义不是同一概念。

编辑器或 H5 随机预览应筛选当前展示范围里完整可用的素材，保留特殊资源手动检查入口。合成像素验证通过与完整玩法还原应分别报告。

## 状态效果分层与帧提交校验（2026-09-08 追加）

人物情绪可能通过独立 OAM 精灵或动态调色板表示。追踪时分别记录外貌配方、头身缓存、符号对象、显存和色表；头像看起来不同不能直接证明替换了五官。零写入 hook 记录也不足以证明没有变化，因为 DMA／批量写可能绕过逐字节 hook。

对符号序列逐帧保存逻辑记录和实际硬件图块。帧边界固定差一帧时，先核查上传与 VBlank 提交时点；不要修改源 duration 来凑截图。使用确定的可见人物快照，隐藏／离屏对象可能不执行动画显示分支。

通过受控修改 RAM 中的符号 ID 验证原动画引擎时，要与正常游玩触发的证据明确区分；不修改输入 ROM。图录命名按实际可见形态，事件的中文语义必须另由业务选择链确认。

## 2026-09-08 追加：兼容原版的像素创编层

1. 模板索引、画布、挂点与像素内容分离。第一版仅重绘非空模板，先保证已有组合接口。
2. 覆盖键包含部件类型、编号、年龄与有效资源组。不能用原始帧地址作唯一修改键，共享地址会造成跨年龄串改；原图缓存与自绘缓存也须隔离。
3. 画板直接编辑 0–15 索引。RGB 相同的色槽不合并，角色换发／肤／衣色才不会串色。
4. 整个笔触是一次撤销事务，绘制时实时预览，结束时更新工程；持久化须遵循用户选择，临时模式不自动存档；工程导入先验证版本、来源、模板、尺寸、字节长度和重复槽再更新。
5. 4bpp 游戏常有自己的半字节顺序，PNG 要按标准重新编码，并用另一套解码器校验像素、色表和透明索引。
6. 空记录要分清「本部件本年龄没有像素」与「提取失败」。模板选择器给出可用数和空数，解释缺帧，不凭空生成挂点。


## 2026-09-08 追加：可调连接点与帧预览

- 区分自身图片锚点与父图片挂接点，分别显示各自的局部坐标；挂接本质是两点重合，子图左上角由父挂点减去自身锚点得到。修改自身锚点时图像移动方向与参数变化相反。
- 先解析完整父子位置，再按原渲染顺序画图。依赖层级不一定等于遮挡层级；双像素取整、镜像和部件自带修正需要在最终位置中保留。
- 名称、引线、虚线及画布外标记使用独立覆盖层，不写入像素或 PNG。像素和定位配置共同参与撤销，但工程 JSON 才携带定位覆盖。
- 同部件多帧用小图列出，编辑帧与播放帧分别标记；空帧明确禁用。预览切帧采用直接按钮，避免菜单遮挡画面。
- 临时创编应将内存更新与持久化分开，跨页查看可一次传递并立即消费；刷新不恢复、旧存档不覆盖，应在 UI 中明确且实际复测。


## 2026-09-08 追加：外设兼容故障的最小验证

游戏的「硬件损坏」提示可能是外设初始化握手差异，不代表 ROM 损坏。先核对源哈希与硬件识别，再对比实际端口操作顺序。缺少用户目标设备时，可用既有 CPU 模拟核心执行原代码，将目标外设访问接到待核查上游源码；记录这是隔离验证，不声称目标整机通过。优先调整协议顺序，不跳过错误分支；以外设禁用仍然失败作为反例，同时保留原始 ROM、生成脚本、差异范围与补丁往返检查。
