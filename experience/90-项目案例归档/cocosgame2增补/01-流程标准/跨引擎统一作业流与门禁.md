# 跨引擎统一作业流与门禁

更新时间：2026-03-10  
来源：多项目复盘重组（Cocos Web / Unity WebGL / TT）

## 使用说明（示例与通用边界）
- 文中 `myprojects/<project>/` 与六大目录是推荐示例结构。
- 若历史项目目录不同，可做等价映射。
- 重点是输入-处理-输出分层、门禁与可追溯性。

## 目标
- 统一 Cocos 与 Unity 的本地化改造流程。
- 把“能跑”与“可交付”拆成可执行门禁。
- 保持项目经验可归档、方法论可复用。

## 统一作业流
1. 建立项目目录（`myprojects/<project>/` 六大目录）。
2. 获取输入并固化来源快照（`input/`）。
3. 还原 Web 工程并本地可启动（`webprojects/`）。
4. 资源与配置导出到可编辑区（`sourceImages/`、`sourceConfigs/`）。
5. 按需求修改并回写工程资源。
6. 运行回归验证（启动、关键 UI、关键流程、资源请求）。
7. 产物沉淀（`output/`）与日志沉淀（`logs/`）。
8. 写项目复盘到 `experience/90-项目案例归档/`。
9. 定期把复盘经验抽取到能力域文档（本目录及 `02~04`）。

## 分阶段门禁
### 阶段 A：启动门禁
- 页面可进入首场景。
- 无新增阻断错误（允许非阻断告警）。
- 资源请求无持续新增 404。

### 阶段 B：内容门禁
- 目标 UI/文案/贴图修改在游戏内可见。
- 如涉及图集回写，合图重建与分图映射一致。
- 关键场景切换后资源可正常加载（避免二关/后续关卡缺包）。

### 阶段 C：交付门禁
- 输出目录结构完整（输入/过程/输出可追溯）。
- 日志、映射、脚本参数可复现。
- 经验文档已归档，目录索引已更新。

## 必留证据
- 本地启动地址与时间。
- 关键日志片段（启动、资源加载、关卡切换）。
- 回写资源列表与校验结果（是否触发 CRC/缓存问题）。
- 产物路径与版本标识。

## 知识重组规则
- 每周至少一次（建议周五）执行经验重组。
- 每个里程碑完成后追加一次重组。
- 项目案例不删，只归档；方法论写入能力域文档。
