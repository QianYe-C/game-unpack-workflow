# 目标平台产物与性能回归门禁

## 构建产物门禁

1. 源码类型检查和编辑器预览通过后，仍须使用目标工具链构建并运行实际产物。
2. 对目标编译器可能改写的语法，检查构建后的模块或 helper；优先验证核心路径中的 Map、Set、迭代器、动态导入与异步启动，不要无依据地批量改写所有同类代码。
3. 用静态 HTTP 服务或目标模拟器覆盖冷启动、主场景、场景切换、跨包懒加载、失败重试和资源释放。分别记录编译、资源请求、初始化、视觉和交互结果。
4. 每次构建绑定源码摘要、工具版本、参数和产物哈希。修复后重新构建；不能把修改过的旧产物标为新构建通过。
5. 清理资源时检查序列化引用、压缩 UUID、动态路径和工具依赖，保存可恢复备份；分别报告源工程、构建包和远程包的大小变化。

## 性能门禁

在同设备、分辨率、场景、进度和对象数量下比较。分开记录逻辑耗时、渲染 CPU/GPU 时间、连续帧间隔 P95、Draw Call、文件体积和运行内存。低 Draw Call 不等于高帧率；传输压缩也不等于 GPU 内存优化。

性能诊断应有显式开关、采样上限和自动恢复；记录计时口径及包含的子调用。缓存固定引用前要验证销毁和场景替换；动态状态仍应实时读取。不能通过只修改计数、降低模拟频率或引入每帧全场景扫描来制造“优化”。
