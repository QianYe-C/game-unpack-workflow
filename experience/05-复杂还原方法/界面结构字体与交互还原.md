# 界面结构、字体与交互还原

整理日期：2026-10-17。资料来源为 cocosgame2 中可读取的经验正文；来源索引见文末。本文将项目案例整理为新项目的操作方法，不增加自动解包、工程转换或编辑器控制能力，也不表示任何新游戏已经通过迁移验收。

## 1. 适用范围与交付边界

适用于把现有游戏迁移为可维护的 Cocos 工程，或修复已迁移工程中的 Prefab、排版、字体、输入与裁剪问题。仅需原构建包本地运行、换图或转换发布平台时，先沿用原有本地化流程；没有需求时不额外重建整套界面。

以下操作需要实际可用且匹配目标版本的 Cocos 编辑器及 MCP/EditorExtends 等控制能力。目标版本、插件与 API 未确认时先完成资源盘点、来源映射和验证计划，记录缺失能力。本文中的工具行为来自特定版本和项目，使用前须在当前工程验证。

每个待还原界面至少交付：

- 原版对象到目标场景、Prefab、组件、字体与图片的映射，保留稳定 ID、来源文件和哈希。
- 保存后的独立 Prefab、正式场景中的关联实例及引用检查记录。
- 原版和目标的同状态截图、操作记录、实际视口与证据版本。
- 已确认行为、项目适配差异、假设和未验证事项，分别列明。

### 证据分级

| 标记 | 可以支持的结论 | 不可以代替的证据 |
|---|---|---|
| 原文件事实 | 某字段、资源、代码分支在该输入版本中存在 | 该字段当前被使用、该界面当前可见 |
| 原版自然运行 | 指定设备、场景和操作中的实际行为 | 所有状态、全部设备都如此 |
| 原方法受控采样 | 声明输入及替身边界后的原方法输出 | 正常游戏必然走该分支、真实 SDK 已接通 |
| 目标结构检查 | 某资产保存、引用和组件类型正确 | 实际可交互、视觉或平台性能通过 |
| 目标运行检查 | 指定构建、视口和流程可以运行 | 原版等价、完整游戏验收 |
| 推断／待确认 | 根据有限证据提出下一步验证方向 | 已实现或已验证 |

不得由目标代码同时生成“期望值”和实际值来证明还原准确。原版样本、来源快照和独立测量应作为对照。来源案例报告的测试数量、误差、字体容量、字号、阈值和时间仅属于该案例，不能直接成为新游戏默认值或验收容差。[S1][S14]

## 2. 按症状选择取证入口

| 症状 | 优先取证 | 后续处理 |
|---|---|---|
| 当前编辑器正常，重开变 MissingScript、字体丢失 | 保存组件类型/CID、字体与资源引用、正式场景磁盘状态 | 第 3 节 |
| 长文重叠、滚不到底、隐藏页签首次打开错位 | 真实父级、Layout/Widget 属性、Label 实际尺寸、旧坐标 | 第 4 节 |
| 字体图集正确，文字仍偏移、描边不一 | 实际 glyph 指标、顶点、材质、字号与回退链 | 第 5 节 |
| 输入回显正确，编辑、光标或选区错误 | 业务值／显示串／DOM 值、字符索引、原光标网格 | 第 6 节 |
| 列表空白、条纹越界、圆角变矩形 | 原 Mask 类型、enabled、显示开关、PPU、运行材质阈值 | 第 7 节 |
| 图片尺寸相同，遮挡或随动仍错误 | 世界四角、父变换、相机、实际排序消费路径 | 第 8 节 |
| 首次懒加载错位、关面板后反馈消失 | 静态引用及运行时查询、常驻服务、历史 resize 与异步代次 | 第 9 节 |

先排除输入缺失和旧编译资源。源文件已保存、MCP 返回成功、浏览器没有 error，均不足以证明当前画面使用了新实现。[S1][S2]

## 3. Prefab 制作、CID 与保存后重开

### 适用与症状

用于新建、复制、拆分或批量修改 UI Prefab，尤其是临时制作实例正常，重开后出现 MissingScript、空字体、默认按钮效果、断开的滚动条或失效嵌套引用时。

### 取证

1. 记录原版节点稳定 ID、父子与兄弟顺序、组件实际类型、enabled/active、UI 层、资源和跨节点引用；区分脚本元数据字段与真正执行逻辑。
2. 分别读取独立子 Prefab、包含它的父 Prefab 和正式场景实例。检查嵌套关联、位置覆盖和实例默认值；节点数量相等不代表字段或关联等价。
3. 对已有工程保留修改前快照和指纹。先查批量操作的每一项结果，顶层 success 可能包含单项 failed。

### 实施

1. 通过当前可用编辑器接口创建只含原生组件的骨架，再进入 Prefab 编辑模式绑定自定义脚本与资源。UI 根和子节点明确使用适合当前工程的 UI 层，不依赖工具默认值。
2. 自定义脚本按实际 TypeScript 资产路径挂载，使用工具返回的实际类型/CID 设置属性。类名可见、字段可写，不等于脚本已经以可反序列化类型保存。
3. 对已出现 MissingScript 的组件，先确认并移除实际坏组件，再按资产路径重新挂载；不能仅增挂正确组件而遗留坏引用。记录替换前后的脚本身份与业务属性。
4. 显式绑定字体、SpriteFrame、Button.target、ScrollBar.handle、ScrollView 与 ScrollBar 的双向关联等。资源引用使用工具当前支持的类型与节点路径解析方式，并读回检查；不假设传入任意 UUID 对象都会绑定成功。
5. 设置组件后最后复核尺寸与交互默认值。Button 的缩放、过渡和禁用态必须来自原版行为或明确的适配要求。
6. 保存、退出、重开独立 Prefab，检查真实组件类型/CID、引用、层、父级、顺序、尺寸与默认显示；再重开父 Prefab 和正式场景核对关联实例。
7. 节点移动、排序或删除后重新查询真实树。引擎可能在帧尾才完成删除；确认旧节点消失后再做依赖该结果的操作。工具 reorder/move 返回成功时，也要读回父级与兄弟顺序。
8. 清理临时制作节点／安装组件后保存正式场景，检查磁盘引用已清理，再移除临时脚本资产。Prefab 保存成功不能证明 scene 也已保存。

### 验收

- 独立 Prefab、父关联实例、正式场景三处均可重新打开，脚本类型正确，无 MissingScript、重复脚本、断链或未解释覆盖。
- 字体、图片、滚动条、按钮和控制器引用均按类型读回；关键节点的状态与来源逐字段比较。
- 当前版本真实运行包含首次打开、关闭再开、切场景再回、禁用／销毁路径。
- 构建日志无缺失类／脚本记录；不能只检查退出码、Finished 或节点总数。

### 边界

案例中出现过 builder 把类名当 CID、复制丢字体、UUID 绑定失败和 siblingIndex 不生效，不表示所有工具版本都如此。应保留当前版本的最小复现。本文不建议直接修补 scene/prefab/meta 序列化来绕过编辑器检查。原案例的“禁止运行时生成 UI”等用户约束属于原项目；新工程若选择可编辑 Prefab 路径，应预制结构、运行时更新已有组件或实例化已制作的 Prefab，并将偏离此路径的实现单列说明。[S1][S13]

## 4. Widget、Layout 与动态内容

### 适用与症状

用于多语言长文、可变高度卡片、网格、页签、滚动条、屏幕适配、动画与布局互相覆盖等问题。

### 取证

1. 读取原版盒模型和实际测量：布局容器、文字行盒、背景、装饰、滚动视口分别占多少空间，绝对定位元素是否参与排版。
2. 同时记录设计分辨率、宿主窗口、实际 frame/canvas、DPR、缩放和安全区。预设名称不等于真实渲染尺寸；手机覆盖式滚动条与桌面占位式滚动条分别测量。
3. 检查 Label 字体/overflow/行高、UITransform、Layout.type/resizeMode/isAlign、padding/spacing、Widget 目标和边距，以及隐藏页签的保存状态。

### 实施

1. 先确定排版策略，再设置字体、字号与字符串；最后设定并读回 UITransform 尺寸。新增 Sprite 时先选择合适 sizeMode，再赋帧并核对尺寸。
2. 设置 Layout.type 后单独设置 resizeMode，再读回保存值。部分版本的 type 变更会重置 resizeMode；不要假设批量属性顺序无关。
3. 可变长文本按实际高度组织；标题在 Layout 中占真实高度，容器随内容增高，超出视口交给 ScrollView。九宫格背景宜与容器同节点，或明确排除在布局外，避免被算成一个内容项。
4. 将布局占位和动画视觉分层：外层负责 Layout/Widget，内层保留固定占位并播放缩放/位移动画。不要让同一节点同时被 Widget 和动画反复改写同一属性。
5. 改父级或布局类型后检查旧 x/y；横向 Layout 不一定清掉旧纵向偏移，isAlign=false 时 padding 也不一定改正旧坐标。重新设置 Widget 边距前先完成必要的尺寸／位置修改，再读回最终值。
6. Widget 优先指向受支持的父／祖先容器。兄弟目标、跨层引用须验证当前引擎和工具行为。图标、焦点、角标放在符合原语义的位置，不让装饰挤入 Grid，也不误放进进度条 Mask 内。
7. 列表行变高后，用实际行底、锚点和视口计算滚动目标，不能继续“索引 × 固定行高”。ScrollView、ScrollBar、handle 双向检查，验证滑块长度和位置都在变化。
8. 屏幕变化时按依赖顺序更新：Canvas/Widget 对齐、相机对齐、内容及滚动布局；首次延迟实例另按第 9 节补算。隐藏页签按需临时激活完成布局，验后恢复默认状态。
9. 跨引擎行盒不一致时，分别比较可见字形与父布局占位；有证据后才增加局部适配。Tamaweb 的额外 0.26 行高是该案例实测结果，禁止全项目无条件减去此值。

### 验收

最少覆盖目标语言、空文案／长文案、多图标换行、隐藏页签首开、滚动到底、关闭重开、横竖屏与 resize 往返。记录 ready、scrolling、settled 三个阶段的实际边界，等待动画稳定后再判断滚动结果。检查文字／背景包含关系、最小间距、重叠、焦点与点击区；用旧错误尺寸、零间距等反例确认门禁能发现已知缺陷。

### 边界

原版存在拥挤排版时，是否增加留白由当前需求决定，并记录为适配差异；不继承案例中的 C14 等项目专属偏好。模型和边界检查通过仍不表示字体光栅、阴影、DPR 与所有像素已匹配。[S1][S2]

## 5. 字体图集、实际几何与缓存

### 适用与症状

用于原图正确但字形偏移、中文／Emoji 缺字、粗斜体不一致、富文本换行错误、按需字体打开后丢失或内存不释放等问题。

### 取证

1. 保留原字体文件／图集、字体资产、glyph 表、字符映射、许可证和哈希；记录回退顺序、默认字符与 Emoji 路径。
2. 核对真实渲染器消费的数据，采集 glyph 的 advance、bearing、baseline、ascender/descender、字体尺度、字距、换行、自动缩字和实际顶点。图集中一个像素格的大小不等于最终文字网格尺寸。
3. 对 SDF 字体读取实际材质、GradientScale、padding、描边、粗斜体、顶点色和世界缩放；不要仅看 Label 上的字号或 isItalic。
4. 采样普通字符、空白、中文、扩展字符、Emoji、缺字、大小字号混排与长段落。未激活对象先确认初始化／OnEnable 副作用；未初始化 textInfo 为空不能当成无字。

### 实施

1. 先建立普通文字基线，再按来源证据加入回退、多页、富文本、缩字和禁则换行。保留原字符串，字符落在哪个字体／材质组须可追踪。
2. 自定义网格不会自动继承所有 Label 排版行为。斜体、额外 padding、不同字号的描边参数等，按真实顶点和原实现恢复；必要时按字号／字重／材质分组，不用统一材质强画整行。
3. 新字体或补字后检查实际使用字符，禁止静默依赖系统字体掩盖缺字。补字需保留来源、白名单、构建方式与许可，不能以“字表覆盖”宣称光栅也一致。
4. 大字体图集避免全量硬引用到首页 Prefab：先加载元数据，按实际文字加载纹理／字形，记录用户引用、共享缓存和回收条件。缓存实现须保留活跃用户，关闭后释放，重开可重建。
5. GPU 复制验证 RGBA，特别是低 alpha 与前一 draw 混合状态不同的情况；恢复纹理/framebuffer 等状态，诊断读回限制在专门验证路径。WebGL 某个后端的修正不能未经验证推广到小游戏或其他后端。

### 验收

- 独立原版样本的实际网格、颜色与排版对照；容差依据坐标尺度、浮点精度和采样方式制定，并保留最大误差与失败样本。
- 真实界面检查长名字、换行、滚动遮罩、混合字体、文字切换与字号变化。
- 首开、关闭至回收时刻、重新打开和销毁后，记录 GPU 页／字形／引用／字节及重建结果。
- 资源按需加载、目标平台首次显示耗时、内存与包体预算分开验收。

### 边界

Idlecat 的 68 组几何或 31 行名字验证属于已报告的局部样本；原项目仍明确保留任意 TMP 标签、编辑态、真机与包体问题。字体按需加载不自动降低发布资源总量，也不证明真实线上排行或昵称服务已接入。[S3][S4][S5][S6][S14]

## 6. 输入值、显示串、光标与选区

### 适用与症状

用于昵称、兑换码等输入。特别关注失焦回显正确，但编辑态字体、光标命中、中文 IME、选区或取消行为不一致的情况。

### 取证

分别采集并保持四种身份：业务原始值、DOM／系统键盘值、渲染显示串、排版字符及源索引。读取原长度限制单位、字符校验／大小写规则、取消语义、焦点、selectionStart/End、滚动和键盘配置。UTF-16 代码单元、Unicode 码点、可见字形不是同一个计数。

原自然运行与受控调用的光标样本分开记录。Idlecat Android 样本由系统键盘绘制光标；原 TMP GenerateCaret/GenerateHighlight 的受控输出，只能证明对应原地编辑分支的几何，不证明正常 Android 屏幕当时就显示该网格。[S7][S8]

### 实施

1. 在 Prefab 中预制文本、占位文本和必要绘制节点，显式绑定字体和输入组件引用；DOM／系统键盘继续承担当前平台所需的键盘及 IME 输入。
2. 校验后的业务值回填 DOM 时同步映射选区，防止组件 string 已变、正在编辑的 DOM 仍旧。大小写扩展等转换按源规则处理，不套用语言习惯推断。
3. 若原显示串附加零宽字符，限定在显示层；不得混入提交值、长度限制、剪贴板或键盘回填。Idlecat 的 U+200B 是实际样本，不是所有输入框的通用规则。
4. 光标和选区从文字渲染共用的布局结果取得 origin、advance、ascender/descender、行指标与索引映射，避免两套排版。混合字体不得统一采用主字体高度。
5. 字段名 caretWidth 不代表最终像素宽。读取原网格或绘制输出后确认字体与尺度换算；原案例 caretWidth=1 得到 2.725 设计单位，只是特定字号和字体参数下的结果。
6. 测试正／反向选区、空跨度、首尾位置、代理对边界与混排。目标实现若仅支持单行普通文本，必须声明不覆盖多行、richText 标签索引或 IME 预编辑。
7. 原文字、光标和选区尚未正确绘制前，不先隐藏浏览器文字／光标。隐藏 DOM 文字后仍用系统字体宽度进行点击定位，会保留错误命中；点击、拖选、滚动和闪烁需各自实现与验证。
8. focus、blur、取消、disable、销毁时清理同步监听和自有绘制状态；重复聚焦不重复登记。测试输入不触发真实提交／领奖时，验收报告明确这一范围。

### 验收

从新项目实际输入规则选择样本，至少检查空值、限制边界、中英混排、Emoji／代理对、缺字、全选、取消、失焦重聚焦、DOM 回填、关闭再开和 IME。光标几何纯函数、Prefab 绑定、浏览器编辑、移动系统键盘及目标平台分别记录状态。按实际需求追加粘贴、删除、左右移动与拖选测试。

### 边界

来源中的“65 个原生几何样本”阶段明确尚未绑定浏览器输入 Prefab，闪烁、命中、拖选、滚动和 IME 仍待确认。可复用的是取证与分层方法，不能把待办写成已经实现的完整输入控件。[S7][S8][S9][S10]

## 7. 静态图片遮罩、动态进度与渲染所有权

### 适用与症状

用于滚动列表、隐藏 Viewport、带透明边／圆角的进度条，以及材质合批后裁剪失效等问题。

### 取证

1. 从原组件读取实际 Mask 类型、原生头部 enabled、节点 active、ShowMaskGraphic、图像 alpha、九宫边、PPU/reference PPU、填充方向和材质阈值。
2. 列出目标节点上 Mask、Sprite、Graphics、自定义 renderer 的所有权及运行时实际材质。不能按节点叫 Viewport 推定矩形，也不能因已有目标 Mask 就倒推原类型。
3. 比较启用前后、初始隐藏与随后显示、满进度与部分进度；检查运行时 shader uniform/stencil 链，不止读取保存字段。

### 实施

1. 先按源语义选矩形／图像 alpha 裁剪。隐藏裁剪区域不应额外显示遮罩底图；ShowMaskGraphic 需要可见图时，按当前目标引擎能力制作明确的显示层。
2. Inactive Prefab 的内部 renderer 可能未初始化；切换 Mask 类型前检查冲突组件，必要时通过编辑器明确移除旧组件并建立所需组件，再保存重开。不能依靠空缓存判断原组件不存在。
3. 九宫格几何边框与纹理 UV 边界分开换算。PPU 会影响几何尺寸，不应通过同步改 inset 破坏原图采样。
4. 动态进度通常需要“完整图像 alpha 范围 ∩ 进度矩形”，保留原图边框、移动条纹和显示语义；不要为了缩短填充而压扁完整九宫格。
5. 低 alpha 原图先查运行材质阈值是否生效。Cocos 某版本中序列化阈值存在但未传入材质的案例，不能靠改亮／换图掩盖。
6. 合批替换裁剪时检查每个后代 shader 是否消费新裁剪属性；仍走旧 shader 的条纹或后续启用项应保留可用的完整 stencil 链。优化前后视觉与性能分别计量。

### 验收

检查静态圆角和透明边、0%／中间值／100%、移动条纹、滚动边界、隐藏后显示、关闭重开、切场景和销毁。对照源 enabled 与 ShowMaskGraphic，检查保存组件及实际运行裁剪；保留低 alpha 和冲突 renderer 反例。构建／Web 正常不代表全部平台裁剪一致。

### 边界

来源的阈值 0.001、PPU=200/reference=100 和实例数量均为 Idlecat 配置。新游戏须重读取值。组件冲突与编辑器故障先后发生不等于根因已证明；保存超时先检查真实状态，不继承原项目重启授权。[S9][S11][S12][S15][S16][S26]

## 8. 世界／局部坐标、动态尺寸与绘制顺序

### 适用与症状

用于换图后尺寸／锚点漂移、子物体随动不对、同层遮挡错误、父组之间层序错误等问题。粒子积分和碰撞本身需另按运动还原方法验证。

### 取证

1. 同时读取原对象及父链的局部和世界变换、锚点、尺寸、图像帧、相机。先比较世界四角，排除尺寸／父偏移后再讨论排序。
2. 动态换图时读取实际帧尺寸和 SetNativeSize 类调用；精灵自身锚点与父挂接点分别记录。复制原对象后显式验证世界位置，不能假设脱离父节点仍保留相同世界变换。
3. 获取实际 sorting layer/order、材质队列、相机透明排序方式、sort point 和包围盒中心。元数据里的 SortingOrder 只有被运行代码消费才会影响绘制。
4. 同层对象可能继续按相机距离排序。采样当前动画变换，区分 renderer bounds 中心、发射器 pivot 和粒子平均位置，不用其中一个冒充另一个。

### 实施

1. 按目标引擎坐标方向、单位和矩阵顺序显式换算，先验证父偏移／旋转／非均匀缩放。涉及像素取整时确认原版是在父坐标与相机累加前还是之后取整。
2. 动态换帧后按源规则同步尺寸、锚点、子文字朝向与相关布局，不靠一次初始 Prefab 截图判断。
3. 原渲染采用跨组全局层序时，以编辑器中保存的层宿主／绘制槽表达该规则；避免逐个父组输出而让一整组压住另一组。
4. 同对象本体与高 order 血条需要全局分层时，保留逻辑控制与原图像引用，使用明确宿主隔离绘制层。在布局、显隐和复用事件更新静态对象，避免每帧全场景扫描。
5. 必须动态排序的少量对象，在动画／模拟更新后的正确时机，用当前相机和真实中心计算；只有顺序变化才修改既有槽索引，空池保持稳定。不要为了绘制方便改变原模拟父级／空间。

### 验收

先验世界几何，再验排序；覆盖换图、动画最大缩放、前后交叉、相机变化、死亡／显隐、对象复用和再入场。分别记录字段检查、规则样本与真实画面；相同截图尺寸仍需保证同相位与同状态。固定前后顺序只在原版证据支持时采用。

### 边界

某组包围盒坐标误差很小、某次战斗能结算，不证明全部随机轨迹和像素等价。源码／枚举字段不能跨引擎直接照抄；动态排序方案也不能只凭“更像”就替换原版规则。[S14][S17][S18][S19][S20]

## 9. 按需模块的布局和生命周期

### 适用与症状

用于把常驻 UI 拆成 Bundle／Prefab，或发现未打开面板时提示、奖励、音效、横幅与交易反馈丢失，首次打开布局错位等问题。

### 取证

1. 同时检查序列化引用、getComponent／节点路径查找、交易后事件、音效监听和外部入口。Prefab 内部引用少不能证明模块可独立卸载。
2. 为每个副作用登记“首次未加载、面板打开、关闭、禁用、销毁、换场景”时应由谁负责；区分数据／服务寿命和界面寿命。
3. 记录启动时及随后 resize 的布局规则，找出延迟实例错过的累计偏移。区分已有世界位置与尚未应用的布局修正。

### 实施

1. 先解除公共依赖再拆资源：公共提示、交易后反馈、必要音效和状态维护由常驻服务／已制作节点负责；面板只处理自身动画与展示。不得为了显示一句公共提示加载整套功能 UI。
2. 同一模块的并发加载合并，缓存成功结果；“最后一次意图生效”或其他切换策略须符合项目需求并明确。失败可重试，关闭／换场景／销毁后迟到回调不能操作旧对象。
3. 加载后的新实例先应用一次源布局规则及累计尺寸差，再接续后续 resize。以实例身份记录是否已补算，重复登记／adopt 不累加偏移。
4. 按需节点登记时立即读取当前状态；重复登记不重复绑定按钮和事件。注销带实例身份，旧实例的延迟注销不能清除新实例。
5. 监听者不能依附于它自己会隐藏而失去刷新机会的节点。回调与等待调度在成功、超时、关闭、销毁时终止；按当前引擎验证 scheduleOnce 等真实调度语义。
6. 字体／材质／计时器／音效的释放按自身所有权完成一次，处理首次用户交互后的迟到回调。仅在有源版本证据时增加后端局部适配，不套用其他项目私有字段。
7. 拆分前后逐字段比较既有视觉与业务引用；只允许用源类已知默认值归一化保存新增字段，不忽略未知差异。

### 验收

覆盖首次从未加载、多入口并发、打开前取消、打开后关闭、失败重试、换场景、销毁后回调、旧实例注销、新实例登记及模块加载顺序排列。横竖屏及多次 resize 与拆分前规则比较；实际触发公共提示和交易后反馈，确认遮挡与消失时刻。

分别量化首页节点初始化、首次打开耗时、帧时间分布、DC、CPU/GPU 内存和发布包体。截图上的 60 FPS 或更少 DC 不能替代同输入采样；减少首页常驻节点也不必然降低资源总量。

### 边界

原案例的 Bundle 大小、回收延时、节点数和浏览器性能不能用于承诺新游戏效果。纯函数／mock 调度通过不代替实际浏览器及目标平台；真实广告、支付、云端服务和 SDK 未接入时明确保留该状态。[S21][S22][S23][S24][S13][S25]
