# 资产身份、关卡与配置还原

整理日期：2026-10-17。适用于资源已能提取，但内容错位、引用不全、关卡数量或实际生成结果不一致的迁移。

## 身份映射先于改名和分类

建立 `来源包哈希 + SerializedFile/资源文件 + 对象ID + 实例作用域` 到导出文件、目标资产 UUID、场景/Prefab 使用位置的映射。Unity PathID 只在所属文件中有意义，同 Prefab 多实例还须区分实例；Cocos 压缩 UUID 与完整 UUID、bundle 和哈希版本要一起保存。

不同名称表和渲染表不保证同序。SpriteAtlas 以 render key/PPtr 等真实关系映射，跨包元数据一并读取；先验证已知对象，再做批量裁切、命名与回写。记录原始文件哈希及修改后哈希，不按显示名去重或覆盖。

本库 Cocos 图片工具目前输出整张纹理及 manifest，回写要求尺寸保持；它没有自动完成完整 SpriteFrame 分图重排与重建。Unity 分图链路也需先验证项目资源结构。需要可编辑 Creator 工程时，应额外恢复 SpriteFrame 元数据、图集边距、旋转/裁切与引用。

## 保存态和运行态分别取清单

1. 保存原 Prefab 层级、active、碰撞体、材质、引用与变换。
2. 追踪 Init/Reset/Enable/关卡创建/模式选择实际调用；记录加载完成后、选择互斥方案后、运行开始时的对象清单。
3. 动态生成器、传送门、收集物、默认内置 mesh 和 shared resources 单独登记；不能因导出目录没有文件就认定原对象不存在。
4. 合批只改变渲染组织，逻辑ID和碰撞身份独立保留；父级会动画的后代不默认静态合并。
5. 对外 `ready` 应在关卡对象、资源引用和必要初始化完成之后发出。下载完成只是其中一步。

常见错误是把 setup1…N 全部保留，而原版只选择其中一组；或只恢复序列化 active，从而多出障碍、碰撞和绘制。代表关卡应在原模式与实际方案选择后确定。

## 关卡覆盖不能只数文件

分别统计入口注册、显示条件、实验分组、主线独立布局、无尽顺序、去重资源、重复周期和未开放内容。配置 `unlock` 等字段要追到实际读取函数；包内多份 Prefab 不代表多个入口，多条顺序记录也不代表同样多的独立布局。

按机制建立覆盖表：普通/奖励/循环、互斥方案、特殊材质、动态生成、不同碰撞层、不同粒子/动画与跨包路径。一个机制至少有真实可达关卡和操作证据；随机/组合机制还须覆盖组合而非只测最简单关卡。

## 配置按消费者、默认值和实际来源恢复

先区分内置表、缓存、网络响应、客户端补字段和运行时派生值。缺字段、显式 null、0、false、空串和“无缓存”可能走不同路径；按原序列化器及实际分支建立样本，不补上凭常识猜测的默认值。

保留包内版本、请求组、时间来源、字段顺序和内容哈希。服务端 MD5 相同不代表客户端缓存字节相同；补字段与排序会改变内容。关卡/活动表的购买窗口、持续时间和清理截止也不能因字段同名就合并。

涉及活动和远端业务时继续使用 [业务存档手册](业务存档服务与跨模块还原.md)。

## 索引像素与部件角色

先确定原存储是逐行、图块还是运行时重排，保存源字节、缓冲区和显示结果。每帧保留地址、尺寸、头、索引像素、palette、透明索引和空帧原因。RGB相同的索引不可合并，镜像、符号扩展、挂点和最终取整次序按源调用恢复。

用原合成函数建立独立像素/调色板样本，再用实际游戏画面交叉核对。身体/头/五官依赖层级不一定是绘制层级；图像自身锚点与父挂接点分别记录。发现眨眼素材只证明有像素形态，是否眨眼、说话或表达某情绪仍须有状态与时序证据。

## 分组网格、材质和交付

多关网格可按内容组打成多 Mesh glTF；去重需比较顶点属性、索引、绘制模式，不能删除颜色、UV、切线来凑数量。一个源 glTF 不代表运行时加载全部子 Mesh；导入后读取真实子资源 UUID 再改引用，检查 imported 状态及子资源数量，删除旧文件前保留备份。

Unity→Three.js 的预设顺序按原 Transform 子节点，不能按文件名排序；每个 renderer 的逆绑定矩阵独立保留。材质关键字、颜色空间、透明与 cubemap mip/HDR 规则逐项核对；自定义网页 shader 不会自然成为可移植 GLB 材质。

## 验收与输出

| 层次 | 必须留下的记录 |
|---|---|
| 原资源 | 输入摘要、对象类型数量、跨文件引用、缺失/占位/不可读项 |
| 映射 | 原身份 → 导出文件 → 目标 UUID → 使用对象；双向可追溯 |
| 配置 | 全表覆盖、实际消费者、模式/分组/默认值/运行时补字段 |
| 运行态 | 初始化前后清单、互斥对象、动态物体、关卡就绪事件 |
| 视觉与玩法 | 已知样本、机制覆盖、原版/目标同条件画面与操作 |
| 修改回写 | 备份、只改预期资源、CRC/版本/缓存与下一包运行 |

资源完整、玩法完整、可编辑工程完整是三项结论。随机布局、物理与收集动画继续查对应手册。
