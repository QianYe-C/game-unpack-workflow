# 业务、存档、服务与跨模块还原

整理日期：2026-10-17。适用于活动入口、奖励、权益、广告、服务器配置、按需界面和持久化迁移。目标是恢复真实条件与时序；离线替身须显式标注。

## 沿实际消费者建立状态图

从字段定义、LoadFromSaveData、实际 getter、事件订阅和提交函数建立调用图，列出状态的来源、读取者、写入者、保存点、通知点与销毁条件。字段名、enum 数值和“已绑定”字样不能直接当业务语义。

同一功能至少分开这些层次：服务资格/分组 → 客户端激活/过期/冷却 → 队列优先级和 UI 锁 → 手动入口/自动弹出 → 外部服务确认 → 本地提交 → 界面反馈。入口未显示可能是条件未满足、刷新顺序不对或父容器被别处覆盖，并不自动表示资源缺失。

## 远端配置与缓存

1. 追踪 GetServerConfig/LoadServerConfig 到真实数据来源。它可能只分派缓存，未发网络请求。
2. 保存内置默认、原始响应、客户端缓存、补字段和最终有效配置的独立快照。记录时间、版本、分组、键覆盖和实际内容摘要。
3. 区分无缓存、缺字段、显式 null、空串、0、false；按原序列化器和消费者恢复。旧 false 必须能覆盖旧存档 true，不能用 `value || oldValue` 破坏语义。
4. 请求中的日期与响应落盘日期保持来源一致；跨午夜按原规则处理。按天/按时刻、本地/UTC、安装日期/归因日期分别确认。
5. 归因 SDK 通知、存档字段变化、前台恢复和重试触发是不同事件。已恢复缓存不代表收到过 SDK 通知；失败预算扣除位置要追真实分支。
6. 同名时长可能分别表示购买窗口、活动持续和回收截止；价格沿商品ID/商品表/货币/显示链路确认。配置字段不证明服务端真的使用了某种个性化定价。

未经原服务实际验证时，交付状态应写“规则/宿主可运行，远端接入未验证”。测试替身不能用“成功”标记掩盖 SDK、交易或账号流程缺失。

## 请求、奖励、保存与通知

将一笔操作写成可追踪状态序列：发起(requestId/存档代次) → 外部确认 → pending/账本 → 本地可靠保存 → 完成通知 → UI/音效。原版有多个保存阶段时先保留其含义；改为原子提交属于明确的实现差异。

必须覆盖：同步回调、重复回调、迟到回调、超时、失败重试、服务确认后本地保存失败、页面关闭/销毁、重载存档、换账号/档位。回调归属发起代次，旧实例注销不能清除新实例；关闭 UI 不应误丢已确认交易。

pending、余额、去重键和消费记录能一起可靠保存时一起提交；保存成功后再发完成事件。每次恢复基于当前完整存档，仅恢复允许字段，避免旧 QA 备份覆盖刚购买的权益或库存。失败回滚使用本次操作前新快照。

外部确认与本地首次保存之间仍可能发生进程中断。需要可恢复交易时，在发起前可靠保存 intent/requestId/幂等键，或具备服务端按请求查询与对账机制；缺少这两者就明确保留该恢复缺口。若原版没有此保证，新增日志/对账属于健壮性差异，不能称为原行为已完全等价。

“客户端不重复发奖”只证明本地幂等。跨服务 exactly-once 需要服务端幂等键、账本或事务协议与真实对照；不得从本地测试推导此结论。

## 权益与广告、支付

永久权益、当前有效权益、历史购买、已领奖与账号绑定分别记录。旧交易/过期权益仍可能证明历史付费；免广告权益不应依赖广告 SDK 当前可用，真实新权益仍须由可信结果发放。

逐模块枚举广告与购买入口，验证永久/外部/缺失权益/只有绑定标志，确保免广告判断没有绕过付费流程。广告计数只跟随真实 earned 回调，不能绑到所有领奖按钮或本地 GM。真实点击与自动路由初始化分开验收。

## 按需模块与常驻服务

UI 可以懒加载，但交易、公共提示、音效通知和 pending 恢复不能依赖某一面板已打开。同时检查序列化引用和运行时 getComponent/路径查找；公共服务使用常驻作者化节点，保持原视觉和生命周期。

延迟加载的 Prefab 可能错过启动 resize/本地化/注册。按原规则补算一次，再验证后续 resize、重复登记和所有加载排列。订阅登记应刷新当前状态并防止重复绑定；销毁时释放所属订阅/任务而不是清空全局服务。

一次性调度的自重注册行为依赖具体引擎。像 `scheduleOnce` 内重用同一函数可能只更新原 timer，返回后仍被取消；用有界调度或明确新任务并在成功/超时/关闭/销毁清理，必须在真实引擎验证。

## 最小回归表

| 场景 | 看什么 |
|---|---|
| 首次无缓存启动、旧档恢复、缺字段 | 有效默认值、初始化顺序、入口是否合理 |
| 货币等普通刷新 | 不反复启动配置请求、不逐帧 JSON 序列化 |
| 跨午夜、归因改变、请求中有新通知 | 请求日期、代次、补发/重试预算 |
| 关闭/重开面板与快速切换 | 常驻服务工作、旧回调隔离、提示样式和遮挡 |
| 服务成功但保存失败 | 不提前通知、可恢复 pending、不重复扣款/发奖 |
| 付费后恢复进度 | 交易/权益/库存等未授权字段保持当前值 |
| 无 SDK 的离线版本 | 缺失路径显式表现为不支持或待接入，不能伪装外部成功 |

输出包括状态图、字段来源表、回调契约、保存恢复样本、原版与目标操作记录，以及 SDK/服务尚未验证范围。继续查 [异步持久化规范](../04-排障与门禁/异步状态持久化与回调隔离.md) 和 [界面手册](界面结构字体与交互还原.md)。
