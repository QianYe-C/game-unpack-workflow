# 粒子、材质与渲染一致性

整理日期：2026-10-17。本文将 cocosgame2 有正文的粒子、材质、GPU 取证和性能案例整理为新项目可执行的方法。归档正文不等于已附带其外部工程、原始 GPU 抓取、采样脚本或通用转换器。

## 适用范围与排查顺序

适用于换引擎后特效形态、持续时间、前后遮挡、色彩或性能与原版不一致的场景。按“实际生效资源 → 出生与模拟 → 生命周期 → 真实绘制提交 → 采样/颜色链 → 整帧性能”排查，每层保留独立证据。

| 症状 | 先取什么证据 | 实施方向 | 必测结果 |
| --- | --- | --- | --- |
| 首帧取错图、粒子形态短暂跳变 | emit/reset/init/animate 顺序和首帧 UV | 只补新生粒子初始化 | 旧粒子年龄和状态不前进 |
| 不同帧率下轨迹、旋转或重力不同 | 系统时钟、年龄、归一化寿命、内部子步 | 按源时间域和取值时机适配 | 30/60/120 Hz 与暂停恢复 |
| 寿命结束后光芒突然消失 | ringBufferMode、容量及后续发射 | 保留暂停/替换语义 | 单次发射、再发射和容量替换 |
| 退出地图后粒子冻结或重入残留 | 地图、发射器、绘制槽启用状态和剩余寿命 | 分开模拟归属与绘制排序 | 退出后自然递减、归零、重入 |
| 同层物体总压在粒子上或反过来 | 实际队列、bounds、相机方向、真实提交 | 按原距离键插入同一队列 | 前后交叉、空池和无重复绘制 |
| 大图接近、缩小后差异明显 | 全 mip 链、采样器和 UV | 保留原 mip/过滤/寻址 | 实际 GPU 层及多个缩放级别 |
| 颜色数值一致但画面泛白/发暗 | 工作空间、上传颜色、shader、目标附件 | 还原完整颜色与混合链 | 独立背景和最终实际像素 |
| DC 已低但 FPS 差 | 主线程、渲染 CPU、上传、分配、帧间隔 | 优化重复查询与热循环 | 同负载平均/P95、长帧与内存 |

## 一、锁定资源和独立样本

### 取证

1. 记录原版与目标的版本、图集/材质/配置/Prefab 摘要、实际绑定对象及引擎后端。读取运行时生效值，不把代码默认值或禁用模块的残留字段当作有效配置。
2. 对每个粒子系统分别登记：发射方式、数量、寿命、速度/尺寸/旋转曲线、shape、空间、变换、模拟速度、环缓冲模式、碰撞、UV、材质、mip、采样器及排序信息。
3. 在源引擎主线程复制原系统，建立受控输入并用 seed、帧号对应连续样本。先采出生，再隔离自由运动，最后加入原碰撞体；不同特效不能因为名字相近就共享结论。
4. 拟合与验证样本分开；改变帧率、朝向、seed、背景或生命周期操作获得独立对照。记录副本及临时相机清理，保持原对象、存档与全局随机状态可恢复。

### 实施与验收

每次修改只说明所解决的层次：出生属性、自由运动、碰撞、生命周期、GPU 输入或最终像素。保留原始记录、分析脚本版本、目标产物摘要和有效采样相位。生效代码需要在预览 chunk 或最终构建核对，工具返回成功不证明浏览器已加载新代码。

与随机、float32、碰撞余量相关的详细步骤见 [原生逻辑随机与物理还原](原生逻辑随机与物理还原.md)。

## 二、出生、积分时钟与粒子时间域

### 取证

将一个粒子从出生到消亡的相位写清楚：发射事件 → 初始属性抽样 → shape 局部位置/方向 → 发射器/世界变换 → 首次模块求值 → 积分 → 碰撞 → 寿命/旋转/尺寸/UV 更新 → 顶点提交。

曲线的横轴必须核实：系统运行时间、粒子年龄和归一化寿命不是同一时间域。暂停、simulationSpeed、延迟发射、循环和短寿命样本有助于区分；不能只把两条曲线的控制点原样复制。跨引擎重力、旋转或速度模块的名称相同，也不证明积分顺序相同。

对出生属性检查相关性和调用顺序。原版可能为速度、尺寸、角度和寿命分别抽样，目标引擎可能共用一个随机比例。统计相关性与分布检验用于发现差异，不能证明恢复了原随机数流。

### 实施

- 对 emit 与 update 分离的引擎，确认首帧属性是否已经适合渲染。必要时只为新生粒子做 `dt=0` 初始化，不推进全部现有粒子。
- 对内部子步和 dt 衰减按原样本适配；旋转/尺寸究竟取步初还是步末寿命必须实测。只对取得证据的特效开启修正，不全局更改所有粒子。
- 验证空间/shape 枚举名称和实际 getter，不能直接复制枚举整数。shape 变换、父级缩放和世界/局部坐标只应用一次。
- 若源为均匀面积圆盘而目标均匀抽半径，可在已确认条件下按面积律适配，例如归一化半径 `sqrt(u)`；这不是所有圆锥/圆盘的默认修复。保留同一位置推导方向的关系与原随机调用数量。

### 验收与边界

覆盖零推进出生、首帧、完整寿命、30/60/120 Hz、暂停恢复及缩放。比较位置、速度、尺寸、旋转、颜色、UV 和随机消费；旧粒子不得因补初始化而多走一步。条件化出生回放只支持该条件内的几何，不支持逐粒 RNG 等价。

## 三、生命周期与环形缓冲

### 取证

同时采集地图 active、发射器 activeInHierarchy、组件 enabled、粒子 seed/数量/剩余寿命、绘制提交、退出/领取/返回时间。普通流程等到退出时粒子已经归零，不能证明“带存活粒子的退出”行为。

需要受控测试时将其明确标为测试输入：在真实退出前制造一批同源粒子，随后执行正式退出路径。记录正常流程与夹具的区别、数量上限和自动卸载时机；探针到期后的空日志不能视为通过。

对环缓冲读取 Main 的 `ringBufferMode`，不能只看 lifetime/loop。源文档确认 Unity `PauseUntilReplaced` 类模式会将寿命末端粒子保留，等待容量替换；“到期销毁”会丢失常亮效果。

### 实施

如果原版发射器全局存活，不要为了排序把整个服务迁入会隐藏的地图。保留模拟服务和原粒子池，给绘制建立可编辑的占位/槽，槽可随当前模式排序，模拟继续按原生命周期运行。

环缓冲简化只适用于“同时出生的一次 burst、固定寿命、无后续发射”的已确认场景：可在原寿命末端暂停系统。持续发射、混合寿命或需要逐粒容量替换时，必须实现对应保留/替换语义；无限寿命或反复播放不能替代。依赖版本内部时钟接口的实现要隔离，并在引擎升级后复测。

### 验收

- 覆盖正常结束、主动退出、短时返回、快速重入和发射器禁用/销毁。
- 以同 seed 跨状态追踪剩余寿命，检查不冻结、不提前清空、不重复模拟，最终自然归零。
- 记录每帧 UI/3D 的实际提交，存活时按设计恰好一次，空池时为零；关闭绘制不能误暂停模拟，也不能恢复出重复 3D 绘制。
- 环缓冲覆盖首次发射、到期停留、再发射、容量满后的替换、暂停恢复与重入。仅测单次 burst 不证明持续发射分支。

## 四、排序、包围盒与真实绘制队列

### 取证

同一时刻读取 SortingLayer、Order、运行时材质 queue、相机透明排序模式/方向、Sprite sort point、动画当前变换和 Renderer bounds。粒子发射器 pivot、位置平均值、包围盒中心不是同一量。

若原包围盒中心由全部存活粒子的逐轴 min/max 中点构成，应以样本确认；不要直接拿静态缩放比较动画中的几何。源全局排序遇上目标树形分组，或者 2D/3D 分队列，会导致调 siblingIndex 仍无法互相穿插。

检查实际管线和提交队列。例：粒子存在于 sceneModels，却不在 uiModelBatches；只改变节点顺序不会自动进入 Sprite 队列。把整个特效相机放最上层也不能恢复原本动态前后关系。

### 实施

优先复用单个原模型和原粒子流，通过受控绘制桥接插入正确队列。包围盒在现有模拟循环累积；固定物体顺序缓存、变换变化时失效，只在排序关系变化时移动槽。避免逐粒节点/Draw Call、重复复制顶点、每帧全池排序和全场景找相机。

材质或实例未变化时不重复设置/编译 shader。维护模型从原队列移除、UI 提交、禁用、销毁及重入的生命周期契约；不得同一帧 UI 和 3D 双绘。

### 验收与边界

覆盖身体与粒子的前后交叉、空池、相机移动/旋转、动画缩放、首帧、材质实例替换和模式切换。在引擎重置统计之前的有效相位读取提交，注明相位；某案例在 AFTER_DRAW 读取到清零统计，后改 BEFORE_RENDER 才形成有效证据。

几何中心正确不代表最终 GPU 遮挡正确，仍要查看真实画面。参考：[队列缺口调查](../90-项目案例归档/cocosgame2增补/90-项目案例归档/2026-09-28-idlecat-矿山碎石队列缺口-阶段复盘.md)、[绘制顺序修复](../90-项目案例归档/cocosgame2增补/90-项目案例归档/2026-09-28-idlecat-矿山碎石绘制顺序-阶段复盘.md)、[突袭动态排序](../90-项目案例归档/cocosgame2增补/90-项目案例归档/2026-09-27-idlecat-突袭同层泥土动态排序-阶段复盘.md)。

## 五、材质、颜色空间和实际 GPU 输入

### 取证：逐段建立颜色链

```text
源颜色/纹理 → CPU 变换 → 上传顶点/实际 UV → 纹理采样
→ shader 运算 → 透明混合 → 目标附件编码 → 最终呈现像素
```

分别记录每段值与空间。CPU getter 的颜色、实际上传颜色和最终像素可能不同；一个颜色恰好符合某近似转换式，不能证明整个有限输入域都符合。不要凭材质名称推断金属度，也不要因参数开关启用就认定后处理资源已创建并实际执行。

1. 先确认实际 API/后端。公开 GLES 方法存在不等于有调用；原版可能实际走 Vulkan，shader 也可能是压缩的 SPIR-V，而非可直接读到的 GLSL。
2. 将候选 draw 与真实对象关联：绑定偏移、范围、索引、已知中心/角点和原始字节共同验证。扫描内存找到相似 RGBA 不是已确认顶点证据。
3. 对颜色转换用灰度完整 0–255 域及独立 RGB/alpha 排列检验；保留 alpha 与 RGB 的处理差异。对 UV 用不旋转角点、原图方向和屏幕投影确认，不按引擎习惯盲加翻转。
4. 读取颜色空间、shader 变体/关键字、实际 uniform、灯光、运行时 SH、HDR decode 和反射 mip。Gamma 工程不能直接套用现代线性 PBR 加 ACES 后靠参数补偿。
5. 对透明材质核对 culling、ZWrite、混合因子、premultiplied diffuse 和高光 alpha；不要仅对齐贴图。

### 实施：纹理与输出目标一并还原

保留完整 mip 链与采样器；第 0 层 PNG 逐像素一致，不证明缩小时一致。检查原始压缩纹理各 mip、filter、wrap、LOD 和目标引擎是否自动生成覆盖了原 mip。GPU 重建后重新核对材质实际绑定，不能只确认“层数相同”。

需要线性透明混合时先用独立探针检查目标附件实际格式及 resize 后状态。Cocos 3.8.8 案例中，普通 RenderTexture reset 会把请求的 SRGB8_A8 改为 RGBA8，显式 RenderWindow 才保留目标格式；这是已测版本的能力调查，不能直接成为所有项目的生产相机补丁。

接入生产前逐项核对主世界/特效/UI 相机、呈现四边形、清屏、遮挡、透明输出、尺寸变化及耗时。独立三角形或目标格式探针通过，不代表整游像素已一致。

### 验收：三背景与独立验证

冻结同一粒子的状态、视口、相机和渲染相位，在黑、白、灰三种受控背景下采集；使用其中两种识别混合候选，第三种留作独立验证。按需要覆盖全 alpha 与半透明。保留相机、附件格式、render scale、像素区域和误差指标；实验后确认临时相机/目标清理且原相机状态不变。

颜色/尺寸曲线、GPU 输入、混合公式和最终同视口像素分别报告。自定义网页 shader 不会自动随标准 GLB 传给外部查看器；应用画布 PNG 与完整浏览器截图的证明范围也不同。异步截图须在请求时冻结配置名，防止快速切换误标证据。

## 六、DC、FPS 与整帧性能门禁

### 取证与实施

先区分目标帧率限制和实际耗时；确认本次压缩、构建等后台负载的影响，在同设备、分辨率、进度、可见角色/粒子数量与相机下比较。缓存固定引用时验证销毁/换场景失效，可变相机状态、战斗和经济数据仍按正确时机读取。

探针必须显式启用、有帧数上限、自动恢复包装方法；计时注明是否包含子调用。不要靠降低模拟频率、改统计计数、减少原粒子或增加每帧遍历来达到 DC 门槛。

### 验收

| 测量项 | 最低记录内容 | 不能据此推出 |
| --- | --- | --- |
| 逻辑/渲染 CPU | 采样帧数、计时范围、均值/P95、调用和分配热点 | 仅凭某函数变快就说整游更快 |
| 帧间隔与长帧 | 连续序列、平均/P95及同一项目长帧口径 | 瞬时 60 FPS 就表示无回退 |
| DC/上传/资源 | DC、顶点/上传量、内存、材质初始化次数 | 低 DC 就是高性能 |
| 额外查询 | 基线查询、重叠附加查询、不支持次数 | 独立 WASM 微基准等于真机帧耗 |
| 平台构建 | 实际产物、设备、分辨率、后端和流程 | 桌面浏览器通过就表示小游戏真机通过 |

A/B 保持同输入、同负载，预热后交替执行并保留原始序列。允许正确性所需且总帧耗可接受的 DC 增加。新手册不设历史案例的 50 DC 为通用硬阈值。

## 七、交付结论模板与适用边界

每个问题的报告采用“症状 → 原版证据 → 根因 → 实施 → 独立验证 → 实际构建/平台验证 → 遗留”结构。至少列出源/目标摘要、有效探针相位、样本范围、最大残差、额外 CPU/上传/内存成本和清理结果。

分别给出配置与数值、生命周期、真实提交、GPU 输入、同视口像素、同负载性能、平台真机的结论。环缓冲接口、查询后端、RenderWindow 行为和内部 shader 适配均绑定引擎版本；升级后针对依赖重测。旧调查保留原状态，后续修正追加证据，不能把历史候选改写成已上线完成。

本手册的通用能力是取证顺序、适配方法和验收口径。未知游戏的原随机流、完整帧缓冲、多相机链路、全部特效及目标平台仍需逐项目验证。
