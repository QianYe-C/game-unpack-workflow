# 原生逻辑、随机与物理还原

整理日期：2026-10-17。本文从 cocosgame2 中有正文的能力域文档及案例提炼，供新游戏迁移使用；归档案例用于解释方法和证据边界，不代表当前工具已内置对应游戏的适配器。

## 适用范围与交付目标

用于源码不完整、IL2CPP/原生逻辑不可直接移植、换引擎后运动或随机关卡出现差异的项目。适用输出包括：原实现样本、输入状态契约、确定性逻辑模块、物理查询适配层、针对目标构建的验证报告。

先明确这次要恢复到哪一层：

| 层次 | 本层回答的问题 | 可接受的证据 |
| --- | --- | --- |
| 数据与规则 | 表、数组顺序、对象引用、条件分支是否正确 | 原包提取映射、原指令/原函数输出 |
| 确定性逻辑 | 同一完整输入能否产生同一规则结果 | 独立源样本逐项对照、状态与随机消费记录 |
| 引擎行为 | 积分、接触查询、生命周期是否匹配 | 实际安装引擎的隔离探针与受控原版样本 |
| 完整玩法 | 真实操作、切场景、结算、保存能否闭环 | 目标构建中实际流程、状态和资源证据 |
| 外观与性能 | 同视口视觉、帧耗、设备体验是否达标 | 逐帧/像素对照、同负载性能与平台验证 |

前一层通过不能替代后一层。可运行关卡数量、无日志错误、一次相似录像分别只支持各自已测范围。

## 从症状选择取证入口

| 症状 | 优先取证 | 常见实施方向 | 验收重点 |
| --- | --- | --- | --- |
| 同 seed 仍出现不同关卡 | 所有 RNG 实例、子种子分发、AB/难度状态、持久指针、题库原序 | 建立完整初始化契约，重建消费顺序 | seed 往返恢复、完整布局 diff、非 RNG 状态对照 |
| 数量正确但少数物件位置/品质不同 | float32 中间值、候选原序、比较器与平局顺序 | 保持源计算及排序语义 | 每个候选值、排序索引、最终标记逐项一致 |
| 首圈接近、后续越来越偏 | 角度范围、累加/归一化、触发器/碰撞层切换 | 分离控制器和刚体，修正状态边界 | 多圈、交叉路、坡道和路面变化 |
| 不同 FPS 下减速/弹道不同 | 实际 dt、内部子步、力与阻尼顺序 | 按源时间步与采样时机适配 | 30/60/120 Hz 和受控长帧 |
| 碰撞点附近停住、漏撞或回弹方向错 | 步前/步后尺寸、扫掠起终点、余量、初始重叠信息 | 限定条件的查询和剩余时间积分 | 平地/墙/斜面、低速/切向/重叠独立样本 |

## 一、建立独立源样本和可恢复的探针

### 取证

1. 固定输入版本：记录原包、业务二进制、配置表、资源包的摘要，以及原引擎、平台、目标引擎版本和后端。字段布局、指令地址与默认行为都绑定这些版本。
2. 静态分析恢复调用链和数据结构。IL2CPP metadata 或 DummyDll 可帮助定位类型与字段；缺失方法体仍需原指令、反汇编或原函数执行证据，不能把空壳 DLL 当业务源码。
3. 将纯控制规则与容器、场景、物理引擎接口分开。可执行原机器码时只替代必要边界，记录 stub 排除的行为；优先调用原关卡/轨迹生成器取得期望值。
4. 动态探针先只读；需要隔离对象时复制原组件和碰撞体，先核对世界变换与模拟空间。局部空间粒子移到高空后，其局部坐标仍可能接近零，不要再次错误叠加偏移。
5. 设置采样上限和明确终止条件，保存原始数据后再做清洗。识别样本用原对象/粒子身份、seed、帧号和相位，不能按输出数组索引盲配。

### 实施

涉及源引擎对象或全局 RNG 的实验，在适合该引擎的主线程边界执行。保存旧状态，在同一受控操作的 `finally` 中恢复 RNG、临时方法包装和其他改动，销毁副本并释放句柄；记录清理后的状态。不要把取证中的临时输入调整混入正式实现。

保留两组数据：一组用于识别候选规则，另一组改变 seed、朝向、帧率或边界条件，用于独立检验。测试期望值必须来自原实现或独立原指令执行，不能由待测移植实现生成。

建议每个新项目保留下列证据结构，名称可按现有工程映射：

```text
source-identity.json       原包/表/引擎/二进制摘要与版本
input-contract.json       seed、状态、数组原序、坐标和时间约定
native-samples/           原始帧、调用、查询或原指令结果
candidate-analysis/       拟合依据及被否定的假设
independent-validation/   未用于拟合的源样本和比较结果
runtime-validation/       最终目标构建中的实际查询、流程与清理记录
```

最小采样记录应包含 `runId`、源身份、对象身份、原入口/地址、输入、输出、帧号、时间步、采样相位、坐标空间、随机前后状态和探针替代边界。比较报告保留最大误差对应的具体样本，不只给一个 passed。

### 验收与边界

独立原函数执行证明该边界内的规则；新系统上的引擎探针不自动证明历史系统的求解器相同。没有实测的模块明确列为未验证。取证和实现工具可能位于原案例的外部工程，本手册的归档正文不附带这些二进制、日志或可运行适配器。

依据：[原生游戏运动移植的独立验证](../90-项目案例归档/cocosgame2增补/04-排障与门禁/原生游戏运动移植的独立验证.md)、[Pico Rally 案例](../90-项目案例归档/cocosgame2增补/90-项目案例归档/2026-09-08-picorally-pixijs-h5-阶段复盘.md)。

## 二、随机还原：完整状态、消费顺序和排序

### 取证

按实际调用顺序列出所有 RNG 的构造、seed 来源、范围 API、抽样次数、拒绝分支及共享关系。多个无参 RNG 可能由线程随机流分配子种子；只控制一个全局 seed 不足以恢复其关系。

同时记录所有非 RNG 输入：难度/win-rate tier、AB 表、题库与资源数组原序、已解锁内容、持久化循环指针、当前回合状态。看起来随机的 child 分配可能只是持久指针推进。

逐层保存：候选生成 → 数值权重 → 候选原序 → 排序后索引 → 按索引抽样 → 最终位置/品质/标记。若后续按索引取随机项，平局元素交换顺序也是业务语义；不能默认 JavaScript 稳定排序与源排序等价。

### 实施

1. 建立显式输入契约，把 master seed、子种子分发规则和非 RNG 状态一起传入初始化模块。不要让加载纹理或渲染是否就绪决定随机消费或碰撞体是否创建。
2. 使用从独立源取得的测试向量验证 RNG，包括零、负值和整数边界；还原范围 API 的端点及整数/浮点语义。
3. 保留资源原始顺序。先核对候选值，再核对排序，最后核对消费位置，避免靠最终布局手调掩盖上游差异。
4. 对比较器、平局顺序确有证据差异时才实现源排序语义。案例中的 .NET 内省排序是该项目适配依据，不是所有游戏的默认算法。
5. 对碰撞后重新抽样、出生多属性抽样和拒绝路径，验证“何时抽、抽几次、无事件是否不抽”。随机分布相容与逐值 RNG 等价分开实现和报告。

### 验收

- 固定完整输入 A → 输入 B → 输入 A，检查 A 指纹恢复；此检查只证明可重复，仍须与原版完整输出对照。
- 对每个候选数值、排序索引、随机消费序列和最终布局做 diff；覆盖平局、空池、边界数量、模式切换及持久指针推进。
- 若临时调用原函数影响全局 RNG，记录调用前后及恢复后的状态，证明未污染下一场游戏。
- 由原观测速度反推出反弹系数，再回放轨迹，必须标成“条件回放”；该样本中用于反推的量不能同时充当独立验证量。

依据：[VitaSort 关卡随机还原](../90-项目案例归档/cocosgame2增补/90-项目案例归档/2026-07-21-vitasort-android-il2cpp-关卡随机还原-阶段复盘.md)、[矿山布局排序](../90-项目案例归档/cocosgame2增补/90-项目案例归档/2026-09-28-idlecat-矿山布局排序-阶段复盘.md)。

## 三、float32、积分时钟与状态顺序

### 取证

沿原指令或原运行时确定常量和中间值精度。ARM64 的 `s` 寄存器等线索可以确认 float32 路径；源单精度常量在 JavaScript 中变成双精度字面量，可能改变排序或阈值分支。

对时间轴分别记录：输入采样、力/力矩应用、积分子步、阻尼、碰撞、寿命递减、旋转/尺寸曲线和渲染。区分真实时间、缩放游戏时间、系统发射时间、粒子年龄及归一化寿命。固定逐帧比例和按 dt 衰减并不等价。

建立最小刚体探针，只施加已知力或初速度，记录单位换算、质量/惯量、每步位置与速度、角度范围、force 清理时机及步数。需要事件循环或渲染才能推进的引擎，先确认每帧确实更新；Pico Rally 的 SKRenderer 探针曾因从时间零起步而只推进首帧。

### 实施

保留源运算顺序，只在有证据的常量、存储或算术边界使用 `Math.fround` 等精度适配。不要对整个算法盲目补单精度，也不要用全局 epsilon 改写业务条件。数学库函数、舍入和角度归一化的未证明差异单列。

还原原内部子步，而不是一律增大物理迭代数。某 Slime 案例实测为超限保留量 `(1-dampen)^(30*dt)`，30 Hz 再分两次 1/60 秒，旋转取步初寿命；这些公式只适用于已采样系统，新游戏须重新取证。

采样帧应声明处于步前、步后还是渲染前。冻结截图不能额外推进一帧；不要把上一模拟状态与下一帧显示状态直接比较。角度无限累计与源单圈归一化不同，会在多圈后放大偏差。

### 验收与边界

至少覆盖 30/60/120 Hz、暂停/恢复和受控长帧；逐步比较后，再比较完整轨迹。记录最大、分位误差及首次分歧的帧/分支，不能只看终点。多圈、路面、坡道与交叉路须有实际用例。控制函数通过、安装引擎积分探针通过、原机整场同输入轨迹一致是三个不同结论。

依据：[运动独立验证方法](../90-项目案例归档/cocosgame2增补/04-排障与门禁/原生游戏运动移植的独立验证.md)、[Slime 出生与自由运动](../90-项目案例归档/cocosgame2增补/90-项目案例归档/2026-09-28-idlecat-狩猎粒子出生与自由运动还原-阶段复盘.md)。

## 四、碰撞查询、余量与初始重叠

### 取证

1. 读取实际碰撞体、触发器、层、mask、材料与运行时世界变换。接触通知不等于刚体阻挡；地面触发球不能直接当实体地面。
2. 复制原粒子与原碰撞体，在平地、竖墙、正负斜面分别取样；覆盖高速、低速、近切向、零速、向外运动和出生重叠。按接触几何分类，不能先用“误差小”筛出好样本。
3. 记录步前和步后半径、sweep 起点/方向/长度、命中距离/位置/法线、查询标志、余量、剩余 dt 和本次随机抽样。尺寸曲线正确不代表碰撞用的采样时机正确。
4. 使用实际安装的查询后端检查默认行为。初始重叠可能返回 `distance=0` 和与射线反向的法线；该结果不等于真实表面法线或穿透深度。

### 实施

先还原普通飞行，再还原接触响应。核对切向和法向阻尼、每次碰撞的独立反弹抽样、扫掠末端余量、命中后的剩余时间积分。

源样本中的“85% 球扫 + 15% 来向余量”只是一组已验证参数。不要直接应用到新粒子；也不要擅自将 `travel = hit.distance - skin` 截成非负，短回退可能是源接触处理的一部分。

初始重叠需要独立路径。若实际后端支持 MTD（最小平移距离）且证据表明需要它，限定在已确认的重叠条件中查询，并记录不支持的后端；不要为所有粒子无条件增加第二次查询或更改全局默认。零法向速度、多碰撞体和棱角需要额外验证，不能照抄会除以法向速度的早期候选公式。

历史顺序需保留：[初始重叠调查](../90-项目案例归档/cocosgame2增补/90-项目案例归档/2026-09-28-idlecat-粒子初始重叠与物理查询调查-阶段复盘.md) 当时明确 `productionFixed=false`；[重叠后续修正](../90-项目案例归档/cocosgame2增补/90-项目案例归档/2026-09-28-idlecat-粒子重叠接触与圆盘出生分布-阶段复盘.md) 才记录限定 MTD 分支、两个模式与实际浏览器验证。二者都没有证明任意形状或所有后端等价。

### 验收

| 必测项 | 报告要求 |
| --- | --- |
| 原版接触与未命中样本 | 分开计数；检查漏判、误判、出射速度及剩余积分 |
| 帧率、平地、墙、斜面 | 至少一组与拟合不同的朝向/帧率；不能跨系统借样本 |
| 初始重叠、零速、切向 | 检查法线、穿透、有限值、向外运动和后端不支持次数 |
| 精度边界 | 保存原残差；近切向误差按坐标 ULP 与条件数解释，不任意放宽容差 |
| 真实运行时 | 检查查询次数、附加查询比例、循环开销与可见结果 |
| 总帧耗 | 同输入、同负载比较，局部查询基准不能替代整帧性能 |

解析平面夹具、实际 PhysX 查询和完整场景分别声明。真实引擎产生了反弹，也不证明每次都与原随机轨迹等价。具体参考：[Slime 碰撞](../90-项目案例归档/cocosgame2增补/90-项目案例归档/2026-09-28-idlecat-狩猎粒子碰撞还原-阶段复盘.md)、[斜面与低速接触](../90-项目案例归档/cocosgame2增补/90-项目案例归档/2026-09-28-idlecat-粒子斜面与低速接触还原-阶段复盘.md)。

## 五、接入与交付记录

先把已证明规则接到最小模块，再接生产消费者，最后在真实构建验证。源码变化后确认预览 chunk 和最终产物包含本次分支；构建成功不能替代实际玩法。粒子、材质与画面后续按 [粒子材质与渲染一致性](粒子材质与渲染一致性.md) 验证。

交付报告至少写明：

- 源版本与摘要；完整输入契约；新增/修改模块和实际支持的引擎后端。
- 源样本、独立验证、条件回放分别覆盖什么，最大残差与未覆盖条件。
- 静态检查、实际引擎、目标构建、原机同输入流程各自的结果。
- RNG/探针/临时对象清理记录；同负载性能的设备、帧数与测量口径。
- 尚未验证的随机流、棱角/多接触、整场轨迹、视觉或平台能力及下一步具体取证项。

原案例中的设备、地址、阈值、seed 和结果数量是历史样本，不能直接成为新项目的通过条件。本手册提供工作方法，不提供对未知游戏的自动还原保证。
